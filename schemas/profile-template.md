# Reader Profile Schema — 人物传记式生产史

## Purpose

`book/profiles/` 不是 Case 的散文化改写，也不是“成功项目复盘”。

本系列的 reader layer 要回答一个更接近人物传记的问题：

> **这个人是怎样一步步变成后来那个能做出这款游戏的人？在几个关键人生岔路口，他当时处于什么处境、有哪些真实可选项、为什么做了这个选择？**

目标读者尤其包括长期接受标准答案、考试排名与职业路径导向教育、但较少接受“目标如何形成 / 兴趣如何变成能力 / 非标准路径如何被验证”教育的中文读者。

因此 Profile 不只解释“怎么做项目”，还要解释**人生中的选择是怎样被现实约束、兴趣、能力、偶然机会和反馈逐步塑形的。**

这不是励志文学。不得把结果已知后的成功倒写成命中注定。

---

## 1. Life Before the Famous Project

重要人物原则上不能从 `New Project` 或 `Company Founded` 开始。

至少追溯：

- 童年 / 青少年时期真正长期投入的活动；
- 游戏、阅读、音乐、体育、编程、画画、mod、论坛等非正式学习；
- 家庭经济与文化条件；
- 学校教育与是否适配学校评价体系；
- 第一批自己主动完成的作品；
- 第一次收到外部反馈 / 钱 / 工作机会；
- 进入游戏行业前的工作、专业或失败路径；
- 什么能力在正式项目之前已经练了数年甚至十多年。

不要为了戏剧性虚构童年决定论。只有存在来源时才建立因果链。

---

## 2. Life Crossroads / 人生关键岔路

每篇重要 Profile 至少选择 3 个真正改变后续可行选择集合的节点。

推荐表：

| 时间 / 年龄 | 当时处境 | 可行替代项 | 实际选择 | 为什么当时这样选 | 直接代价 | 后来打开的选择权 | Evidence |
|---|---|---|---|---|---|---|---|

适合写成岔路的事件包括：

- 是否继续读书 / 退学 / 转专业；
- 是否接受稳定工作；
- 是否辞职；
- 是否继续做一个拖延项目；
- 是否和某个伙伴合作；
- 是否学习一个新工具；
- 是否公开 prototype；
- 是否接受 publisher / grant / platform deal；
- 是否砍掉一个自己很喜欢的功能；
- 是否保持小团队还是扩张；
- 第一次失败后是继续、转向还是退出；
- 第一次成功后如何重新定义目标。

### 必须回答的反事实问题

不是问“如果他当年没这样做，今天会怎样”这种小说式反事实。

而是问：

> **在当时他真正知道的信息和拥有的资源下，这个选择为什么是可理解的？**

如果当时存在更安全 / 更常规的替代项，要写出来。读者需要看到“非标准路径”不是一句勇敢，而是一个有约束的选择问题。

---

## 3. Goal Formation / 目标如何形成

本系列不预设主角从小就“梦想成为伟大游戏制作人”。

重点记录：

- 目标是在什么时候开始变具体的；
- 什么体验让“兴趣”第一次变成“我想亲自做”；
- 什么外部反馈让目标值得继续投入；
- 什么失败让目标被重写；
- 什么收入 / 同行认可 / 用户反馈让 hobby 变成职业；
- 第一次成功后目标是否又发生变化。

如果一个人的目标长期模糊，也要如实写。

核心问题不是“你从小的梦想是什么”，而是：

> **一个成年人怎样通过行动和反馈，逐步发现自己愿意为哪类问题投入几年人生。**

---

## 4. Play → Capability Chain

当人物存在明显游戏玩家 / modder / critic / UGC / 社群前史时，必须审计：

```text
play / fascination
→ comparison / taste
→ reverse-engineering / modding / rules literacy
→ tool use / scripting / content creation
→ public feedback / community
→ repeated shipping
→ professional capability / market access
```

不是每个人都会走完整条链，也不是“玩得多”就自动获得能力。

必须说明具体转换动作发生在哪里。

例如：

- 玩游戏 ≠ 会设计游戏；
- 但长期比较并写评论，可能形成 selection/taste capital；
- 玩可修改游戏 ≠ 会编程；
- 但改地图、脚本、规则、服务器可能成为低风险的生产训练；
- 参与社区 ≠ 拥有职业网络；
- 但公开作品、协作和被看见可能形成下一阶段 market/career access。

---

## 5. Hidden Supports and Costs

传记不能只写个人意志。

每一个关键跨越都检查：

- 谁付生活费；
- 有没有工资 / 储蓄 / 家庭 / 伴侣支持；
- 住房与地区成本；
- 是否有学校电脑、公司硬件、平台、互联网、社区；
- 是否借用了老板、publisher、同事或开源生态的基础设施；
- 是否牺牲健康、关系、稳定收入或职业安全。

“选择”只有放在可承担的成本里才有意义。

---

## 6. No Hero Predestination

禁止以下写法：

- “他天生就是程序员 / 设计师”；
- “命运从这一刻已经注定”；
- “只要热爱就一定能成功”；
- “学校没用 / 大学没用”；
- “打游戏就会获得未来技能”；
- 用成年成就反推童年每个兴趣都具有目的性。

优先写：

> 某项长期兴趣在一个特定环境中，通过明确行动转换成了一项可验证能力。

---

## 7. End Beyond the Hit

人物篇原则上不能在爆款销量处结束。

继续追：

- 第一次成功怎样改变生活；
- 钱带来了什么选择权；
- 成功是否引发组织扩张 / 冲突 / 目标变化；
- 后续作品是否证明原方法可重复；
- 主角后来是否否定早年的做法；
- 他最终想成为什么样的人 / 公司，而不只是想做哪款游戏。

这样读者看到的是**人生轨迹**，不是一次中彩票。

---

## 8. Reader Promise

每篇 Profile 应尽可能让读者带走四种认识：

1. **目标可以形成，而不一定在十八岁之前被发现。**
2. **兴趣必须经过制作、反馈和现实约束，才会变成能力资本。**
3. **非标准路径不是反对学习；它要求更主动地学习、验证和承担结果。**
4. **成功不是证明某条人生路径普遍正确；它只说明在特定条件下，一组选择如何打开了下一组选择。**
