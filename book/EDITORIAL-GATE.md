# Reader Profile Editorial Gate

本 Gate 属于 **Lane C / Editorial**，但由 Lane A 维护其流程边界。它不创造事实，也不替代 Case / Evidence / Claim。

目的：让 reader profile 真正成为“人物与生产史”，而不是把研究档案换成更顺的论文。

## -1. 先判断你在写 Profile 还是 Chapter

**Profile** 的主角是一个人 / 团队，核心问题是：

> 他 / 他们怎样走到这里？

**Chapter** 的主角是一个现实问题，核心问题是：

> 多个人生放在一起，能让读者更清楚地判断什么？

Chapter 必须做到：
- 至少比较两个已进入 reader layer 的人物 / 团队；
- 不能按“案例 A、案例 B、案例 C”机械摘要；
- 必须存在冲突、反例、边界或不同路径；
- 结论必须比任何单个 Profile 更一般，但不能超过 Claims / Evidence 支持范围；
- 面向非游戏行业读者时，先翻译成人生问题，再保留游戏产业细节。

若只是把 Case 散文化，既不是合格 Profile，也不是合格 Chapter。

---

本 Gate 规定质量原则；涉及已有 reader prose 的去模板化、重写或结构清理时，按 [Editorial Rewrite & Historical Fidelity Protocol](EDITORIAL-REWRITE-PROTOCOL.md) 执行 **Fact Lock → Narrative Packet → Delete / Person / Rhythm → Fidelity Readback → A/B → Author Acceptance**。不得把“AI 味少了”作为不必核对 Case / Evidence 的理由。

---

## 0. 事实边界先于文风

- 关键事实必须能回指 Case / Evidence。
- 不得为了场景感补写 UNKNOWN。
- 不得虚构对话、动作、心理、地点细节或时间顺序。
- P1 回忆必须保持“多年后回顾”的性质，不倒写成同期已知。
- 任何书级 Thesis Candidate 都不能因为文章需要高潮而写成已证实规律。

若叙事需要的细节不存在，宁可写得克制，也不要小说化补洞。

---

## 0.5. 新稿写作入口：预防模板化

本入口适用于新写 `profiles/`、`chapters/`、`life-routes/` 的读者正文。改写旧稿继续执行 [Historical Fidelity Rewrite Protocol](EDITORIAL-REWRITE-PROTOCOL.md)。新稿不能等到发布前才处理人物缺席、理论压过经历和叙事串味。

### 动笔前：事实锁与 Narrative Packet

在任务交付笔记或 PR 中先留下短纸条，不新增 canonical metadata，也不把这些字段搬到读者第一屏：

- **事实锁：** 指明消费的 Case / Evidence / Claim 及版本，列出关键人物归责、时间、数字口径、回忆时点、否定与条件，以及 UNKNOWN / H / Signal 和时效边界。没有来源的关键句标 `VERIFY_IN_LANE_B`，不为叙述补齐。
- **叙述对象与主问题：** 是单人、群像、失败调查还是跨案例问题？用一句话写清本篇读者要追问什么。
- **人物、时代与具体处境：** 当时有什么、缺什么、可选择什么？哪些工具、渠道、资金和非开发支持真正可用？
- **决定与后果：** 选已有证据能承担的行动节点和可观察反馈；不以人格标签、抽象机制或事后成功替代过程。
- **叙述方式：** 从哪个具体入口开始，怎样推进，在哪里结束？与相邻文章比较，说明为何这种方式适合本对象；不为形式差异强造场景。
- **作者观点与文风边界：** 明确要保留的判断、依据与适用范围，区分作者解释和来源事实；列出不能补写的心理、对话、关系和现场细节。

Packet 可复用改写协议中的字段，但它是策划纸条，不是所有文章必须采用的章节模板。证据不足以写出人物行动时，采用克制的说明性叙述，或交回 Lane B；不能生成一篇漂亮传记再倒找证据。

### 初稿：让事实承担叙述

- Profile 从人物的时间、处境、作品状态或决定进入；Chapter 从现实问题和案例之间的冲突进入。Myth 反驳只在确实需要纠错时使用，不作为统一开头。
- 以行动、反馈、代价和后续变化推进；分析紧随能承担它的事实。保留作者的锋芒和判断，不让人物反复替全书宣读同一结论。
- “不是……而是……”、短句、强调句和理论术语均可使用，但要有具体职责；连续反转、例行小节拔高和重复结论先检查是否冗余，不做同义替换式清洗。
- 段落长短随材料变化，重音留给真正改变理解的地方；不将连句成段、减少词频或增添修辞视为自动改善。
- Profile 结束人物的这一段经历和仍在的边界；全书综合留给 Chapter。各篇不用同一开头、节奏与结尾，但也不为了求异改变历史顺序与因果。

### 交付前：初稿也经过三遍编辑

依次执行 **Delete → Restore Person → Rhythm**，再按 [Fidelity Readback](EDITORIAL-REWRITE-PROTOCOL.md#3-fidelity-readback逐项核改写是否改变认识) 回读人物归责、时间、数字口径、否定/情态、因果、回忆与同期、UNKNOWN/H/Signal、历史环境及引语。重复可以删除，必要反驳、作者观点和事实边界必须保留。任何未纠正的历史忠实性倒退均不能用可读性补偿。

交付说明人物具体性、连贯度、观点保存、节奏、继续阅读意愿和历史忠实性的编辑判断，并明确是否有独立审查或实际读者测试。首次新稿没有旧版，不要求虚构 A/B；若比较初稿与修订稿，保存版本并说明是否盲测。词频、短句比例和模型自评不构成验收；作者验收仍是独立步骤，不能自行标为通过。

本入口是人工编辑流程，**不新增 AI 文风 lint、固定禁词表或自动合格阈值**。

## 0.6. 先读当时的声音，再决定怎样讲

本节适用于新稿与既有正文改写，补入现有事实锁、Narrative Packet和Fidelity Readback，不另建验收流程。

- **材料先于提纲。** 动笔前读与人物关键阶段有关的同期采访、报道、试玩/评论和开发记录，也寻找批评、迟疑、失败及不符合作者解释的材料。在编辑笔记记录哪些已全文读、哪些只读选段、哪些未取得；搜索摘要和互相转载不算独立阅读。没有同期材料时明确缺口，不用后来的回顾冒充。
- **区分谁在说话。** 当事人的回答、记者的观察或提问、评论人的体验判断、宣传文案和本书作者的解释分别归属。报道中的直接证词可按说话人与时点判断等级，记者概括不能改成开发者原话。一篇评论不代表全体玩家，几篇报道也不能证明成功原因或群体发生率。
- **保留人物当时可用的语言与认识。** 人物只知道当时已知的结果，可能尚不清楚机制、市场或后果。保留其专业词、具体问题、迟疑和条件，不让引语或转述突然掌握本书的事后理论。作者可以另作分析，但不能把分析放进人物嘴里；不为声线差异模拟未有记录的对白。
- **让来源改变叙述。** 先辨认材料真正提出的问题、行动和分歧，再选开场、顺序与结尾。不能先固定“神话→反转→机制→教训”，随后只用引文装饰它。采访中的自我怀疑、外界未获解答的问题、作品评价中的矛盾，都可能改变叙述焦点；不得剪去反面材料只留下证明作者正确的部分。
- **引用服务阅读。** 在关键节点使用能承担人物立场或外界反应的短引语、带署名转述及就近来源链接，避免全文只剩模型的概括。没有必要引语时不强加；不设每篇引用数量、引文占比或媒体篇数门槛，也不拼接长篇第三方文字代替作者叙述。译引标清来源，核对过去时、否定、情态与上下文；刊出日期不自动等于采访日期。
- **入稿仍服从事实Owner。** 新找到的报道即使已经读完，尚未由Case/Evidence承担的关键事实仍为`VERIFY_IN_LANE_B`。记录拟接入位置和核证问题，不能用引号或记者署名绕过证据摄取；未知与冲突不补齐。

### 为读者备好原文与作品入口

- 引语和关键转述就近提供原文直接链接，保留作者/机构、标题与发表日期；文末整理本人博客、开发记录及相关报道，不要求读者先到Evidence Ledger寻找网页。编辑记录如实登记未读或失效状态；未读材料不充当已核引文依据，直接影响正文理解的缺口用人话说明，不编造地址。
- 文中主要作品首次出现时提供核过作品身份的官方Steam入口；没有Steam页面或所谈的是历史旧版时，可优先链接官网。原免费版、重制版、移植版与后续商业版分别标清，不能让当前商品入口替换历史起源。正文少量就近链接，文末可集中列出作品，便于读者继续阅读或体验。
- 来源链接、作品体验入口与延伸阅读各有用途。页面可打开不等于事实已证；延伸阅读不自动接纳新事实，商店页也不证明历史成功原因。不顺手把动态售价、折扣、评测量写进历史叙述，不设固定链接数或来源数量门槛；未有官方入口时如实保留缺口。

交付时增加两项编辑回读：删去人名后，各篇是否仍由同一个模型的问答、比喻和结论推进；保留引文与已核行动、暂去掉作者总结后，读者是否仍能追随人物经历。前者检查叙述串味，后者检查事实能否承担故事，**都不要求伪造不同声线，也不要求删除作者观点**。说明哪条来源确实改变了写法；没有改变时如实记录，不以增加引文数量宣称可读性改善。最终仍按六维比较与作者验收判断。

## 0.7. 来源表达、双向回读与全文检查（试行）

本节补入已有Narrative Packet、三遍编辑和Fidelity Readback。适用读者叙事正文，包括暂存在research-notes中的书稿候选；不要求Case、Evidence、研究笔记或日常讨论使用传记文风。方法经逐篇试验保留或撤回，不新增人物事实源、声线目录、Schema、检测分数或自动合格阈值。

### 写前：一张表达纸条

在现有编辑记录中简短写下：哪些已读来源怎样提问、表达确定程度、使用技术词或自嘲；哪些特点只出现在某个阶段；本人表达、记者观察和作者评论怎样交接。每项回指已核材料，表达观察不当成人格事实，也不据此生成本人从未说过的对白、心理或判断。作者认可的中文样本优先；没有认可样本就明说，第三方报道与Agent候选不能自行标为AUTHOR_APPROVED。

保留来源中不同方向的行动和认识：想制作也可能停顿，愿意删减仍可能留下更难的工作，回顾的方法未必在开工时已清楚。不能将它们修平成“始终坚持”“总能选对”或稳定的成功性格。写一两个本篇不应出现的反例即可，不把表达纸条变成每篇相同的提纲。

### 改后：按两个方向核关系

- **原文→新文：** 独有事实、动作、作者判断、否定、条件、范围、完成态、比较对象和责任各在哪里保留？删掉的内容必须确属重复或已授权删除。换词后流畅不代表等义，例如“乐趣至多一次”不能变成“只能看一次”。
- **新文→依据：** 新增或改写的每个关键关系，由哪个原句及Case/Evidence承担？重点找暗添的时间先后、必然性、因果、效果类型和人物归责。已有稿件不能独立替代事实源；新发现的关键事实仍交Lane B。没有依据的关系恢复原表达或撤回，不靠追加免责声明掩盖。

不另做一张全库事实表；在现有Fidelity Readback中记录实际发生漂移的子句、修正及未解决问题。独立审读与作者验收仍分开。

### 最后：连读全文再判断收益

逐节正确不等于全文好读。连读开篇到结尾，检查是否反复先概括、再举例、再总结，是否每个小节都同样短促，是否正文夹入了上一稿的编辑说明。只处理实际冗余，必要转场、作者有意强调、技术用语、原话和事实边界仍保留。不强制口语化、随机变化句长或把不同作者写成刻意不同的角色。

译腔另查语境与中文搭配，不能只核对字典词义。职业名词先辨岗位、职责、职级或身份，再检查它与“应聘、担任、负责、转岗”等动词怎样搭配；优先写清具体工作。例如杂志招聘语境的staff writer可写“撰稿岗位”，后续职责可写“转去写稿”，不写“应聘杂志的写作者”。writer并非处处同译，也不能为顺口把它升级成主编、加上自由职业身份或管理权限。陌生职称回查原文和职责，必要时保留原称说明；直接引语不擅改，A/B中的旧译保留为历史版本。这是语境审读，不是“写作者”等词的黑名单。

交付沿用六维比较，附少量原句/改句及编辑收益；可判KEEP_ORIGINAL或REVISE_AGAIN。如实记录是否匿名、由谁比较及是否有真实读者参与；非匿名比较不称盲测，Agent比较不能证明真实读者阅读意愿改善。跨篇复用的是检查方法，不是Gunpoint的八节结构或固定字数。

方法参考（2026-10-09核读，独立转述）：[Humanizer-zh](https://github.com/op7418/Humanizer-zh/blob/main/SKILL.md)的作者声音与模式诊断、[stop-slop](https://github.com/hardikpandya/stop-slop/blob/main/SKILL.md)的具体表达检查、[shuorenhua](https://github.com/MrGeDiao/shuorenhua/blob/main/SKILL.md)的实词与语义回读、[nuwa-skill](https://github.com/alchaincyf/nuwa-skill/blob/main/SKILL.md)的表达维度与张力观察。上述方法各自的整套流程、禁词/禁标点、人物模拟或自动编排不因此成为本库规则；外部效果自述未由本库验证。实践差异见独立Lane C [Gunpoint候选PR #289](https://github.com/TrojanFighter/IndieGameLegendaryHeroes/pull/289)，作者及真实读者验收仍待完成。

**跨模型执行要义：** 读事实与来源 → 留表达纸条 → 按人物经历写 → Delete / Restore Person / Rhythm → 双向Fidelity Readback → 全文连读 → 六维比较 → 作者验收。任何模型都可以保留原句，不为证明工作量强改；方法试行不授权批量覆盖书稿。

## 1. 先让读者遇见人，再让读者遇见理论

Profile 的开头优先让读者看到：

- 一个具体时刻；
- 一个具体处境；
- 一个具体选择；
- 一个具体矛盾；
- 或一个足以改变生产路径的事实。

不要默认从：

> “独立游戏史经常把这个故事讲成……”

起手。

“流行神话 → 反驳神话”仍然可以使用，但不能成为所有 profile 的统一模板。

如果证据允许，前 300–500 字应尽量出现至少一个**人 + 决策/处境**，而不是只出现项目 thesis。

---

## 2. 每篇只保留一个主命题

一篇 profile 可以触及多个 Claim，但 reader layer 需要一个清楚的主问题。

写作前先完成一句：

> “这篇主要回答：________？”

例如：

- Kenshi：一个明显超过单人正常产能的项目，什么时候开始不再只靠一个人的生命时间供养？
- Rocket League：一家公司怎样用服务业务购买组织存续，并保留第二次原创下注的权利？
- FTL：团队怎样把一次高风险创业拆成逐步增加承诺的实验？

次级命题必须服务主问题，不要每一段都重新宣布一个“大结论”。

---

## 3. Reader layer 要少说“研究正在做什么”

以下语言属于 research backend 的正常语言，但在 reader profile 中高频出现会破坏叙事：

- “本案最值得研究的是……”
- “当前证据支持……”
- “从生产史角度看……”
- “真正重要的是……”
- “这个案例证明……”
- “Evidence Ledger 显示……”

这些词不是禁词，但应优先转成：

> 人当时面对什么 → 做了什么 → 直接发生了什么 → 我们为什么因此改变理解。

研究状态、UNKNOWN、证据等级应集中放在 provenance / research boundary 区，而不是不断插入正文。

---

## 4. 控制“不是……而是……”和结论句密度

当前样稿反复依赖：

- “不是 X，而是 Y”；
- “真正的故事不是……”；
- “真正值得记住的是……”；
- “这很重要”；
- “换句话说”。

这种结构适合纠正 Myth，但高频会让五篇文章拥有同一个说话节奏。

编辑时检查：如果连续几个小节都以否定旧解释、宣布新解释推进，至少重写一部分为**时间推进、行动结果或具体矛盾**。

---

## 5. 专有研究词必须先翻成人话

可以使用：`runway`、`scope`、`market access`、`capability capital`、`staged commitment` 等术语，但第一次出现必须先让普通读者知道它具体指什么。

优先写：

> “还能不接别的工作、继续做这个游戏多久”

再告诉读者这就是这里说的 `runway`。

不要连续使用多层抽象词，例如：

> “capability capital 改变 production function，并通过 market-access infrastructure 转成 organization capital”。

研究档案可以这样压缩；书稿不应该要求读者先学术语才能理解故事。

---

## 6. 把具体行动写在人格判断前面

坏：

> 他很有品味。  
> 团队很灵活。  
> 他们非常坚持。

好：

> 他删除了哪些昂贵但不服务核心体验的内容；  
> 团队把 full launch 改成 demo；  
> 公司继续接 work-for-hire，让合同项目覆盖原创团队；  
> 开发者用付费 alpha 把玩家收入换成下一阶段人力。

如果一句人格描述不能被至少一个具体行动支撑，应删掉或降成作者判断。

---

## 7. 跨案例综合不要侵占每篇结尾

Profile 的结尾优先回到：

- 这个人 / 团队；
- 本篇主问题；
- 这一案的 transfer boundary。

不要每篇都在最后重新串一次 Kenshi / FTL / Rocket League / Gunpoint / 其他案例。

跨案例综合主要放在：

- 章节导语；
- book-level synthesis；
- `THESIS-CANDIDATES.md`；
- 最终 TOC / thematic chapter。

个案偶尔引用另一案做对照可以，但不应把 profile 变成全书 thesis 的证明段落。

---

## 8. Provenance 与叙事分层

每篇必须保留 Case / Evidence 回链，但建议分成两个层级：

### 顶部最小 provenance

- 对应 Case；
- Evidence Ledger；
- 必要时一句当前状态。

### 文末 research boundary

集中列：

- 仍 UNKNOWN；
- 关键证据；
- 不可直接复制条件；
- 尚未解决的因果问题。

不要让同一研究状态免责声明在正文中反复出现。

---

## 8.5. 所有“值得学”都必须有年份与时效性

Reader layer 一旦从历史事实推出“今天可以学什么”，必须同时回答：

- **Observed When**：这个做法真正发生在什么年份；
- **Regime**：当时的平台、工具、发行、支付、社区、竞争与成本条件；
- **2026 Transfer Status**：`DURABLE / CONDITIONAL / HISTORICAL / CURRENT / UNKNOWN`；
- **Mechanism vs Tactic**：今天保留的是结构机制，还是某个已经过期的渠道打法。

禁止把“2019 年成功经验”写成无日期的通则。

平台 / 算法 / 商店曝光 / creator discovery / 众筹 / 生活成本 / 融资环境属于高时效变量；未做当前核验时默认 `CONDITIONAL / UNKNOWN`。

完整规则见 [`TEMPORAL-VALIDITY.md`](TEMPORAL-VALIDITY.md)。

---

## 8.6 不得把有媒体报道的成功者当代表性开发者

人物传记依赖一手采访是合理的；**将报道人物的选择过程忽略，再归纳其群体发生率则不合理**。

发布 Profile / Chapter / Life Route 时检查：
- 作者为什么会被我们搜到？获奖、畅销、创业融资、发行商 PR、英文媒体、GDC 演讲、公开失败、玩家社区？写作采样未必由研究者主动控制。
- 报道发生在项目成功/失败之前还是之后？成功后的自述可能重新编排因果顺序。
- 该人物可以证明哪种机制存在？什么比例/国别/普通读者成功率是**没有分母**而不能说的？
- 是否把“没有作品公开记录”错误写成“从未拥有作者性”？
- 所谓“加入失败案例”是不是只加入了**最会讲故事的著名失败者**？
- 一旦文章使用“通常/大多数/中国比美国/某些岗位更容易”等分布判断，必须回指一个预先定义且可观察的 cohort sampling frame，否则删除或标 UNKNOWN。

正式流程：[Creator Visibility / Sampling Gate](../schemas/creator-visibility-sampling-gate.md) 与 [028 样本偏差审计](research-notes/media-selection-survivorship-and-denominator-protocol-028.md)。

---

## 9. 场景化不等于小说化

优先使用已有证据中的具体东西：

- 时间；
- 工作岗位；
- 数字；
- 公开开发日志；
- 决策节点；
- 当事人同期说法；
- 产品当时的状态；
- 失败后的实际动作。

禁止补写来源没有的：

- “他坐在昏暗办公室里”；
- “他当时一定感到绝望”；
- “两人对视后决定赌上一切”；
- 未核验的日常细节。

好的生产史靠**决策细节**产生戏剧性，不靠虚构文学细节。

---

## 10. 发布前人工检查

每篇 profile 升级前至少问一次：

1. 前 500 字能看到“人和处境”吗？
2. 能用一句话说清这篇主问题吗？
3. 是否连续三次以上用 Myth → 反转 → thesis 推进？
4. 是否研究术语比具体行动更密？
5. 是否为了叙事补了 Case 没有的细节？
6. 文章是否把同一个 thesis 说了三遍以上？
7. 结尾是在结束这个人的故事，还是又替整本书写总论？
8. UNKNOWN / transfer boundary 是否仍然清楚？
9. Case / Evidence 回链是否存在？
10. 这篇和上一篇在开头、节奏、结尾上是否明显不同？
11. 所有可迁移经验是否写明观察年份和 2026 时效状态？
12. 是否把某个历史平台 tactic 误写成 timeless mechanism？

## 10.5. 既有书稿重写必须留下可审计差异

- 先保留原文 SHA，明确只改哪些章节；不能无差别清洗全书。
- 先删除重复论点，再恢复人物与行动，最后调整节奏；不能只替换疑似 AI 词汇。
- 修改后的时间、归责、否定、情态、数字口径、来源和 UNKNOWN 边界要做 Fidelity Readback。
- 有条件时对不同版本进行匿名 A/B 对照；不达标可以保留旧稿。
- 由作者确认新稿才合并；Agent 不自动把“更好读”当成批准。

详见 [改写执行协议](EDITORIAL-REWRITE-PROTOCOL.md)。

## Automation boundary

当前 Gate **不进入机械 lint**。

原因：以上问题多数依赖语境和叙事判断。只有未来出现明确、重复、可机械识别的错误（例如 provenance 缺失、链接漂移、固定字段缺失），才升级为工具 / CI。

## 11. 研究元数据下沉，不占读者第一屏

Profile / Chapter 第一屏原则上不出现：
- CASE 编号；
- Evidence Ledger；
- RESEARCHING / SKELETON；
- P0 / P1 / S1 / S2；
- lint / schema / metadata。

这些信息原则上集中到文末的“研究与证据入口 / 研究依据”。

例外只有一种：某个研究状态本身直接影响读者如何理解正文，例如关键争议尚未解决。这时也应先用人话说明，不要先抛后台术语。

Reader layer 的目标不是隐藏证据，而是让证据待在正确的位置。
