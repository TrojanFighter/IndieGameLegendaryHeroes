# 《独立游戏英雄传说》｜第一次来，先从这里读

© 2026 洪荒行者。All Rights Reserved.

你不需要先知道什么是 Case、Evidence、Claim，也不需要按编号读这个仓库。

这套书首先写的是一种很现实的人生问题：

> **当你没有标准答案、资源有限、也不知道自己最后能不能成功时，一个人究竟怎样找到值得做的事，并一步步把自己变成能做成它的人？**

独立游戏只是一个特别适合观察这个问题的样本场。

因为这里的人通常钱不多、团队很小、失败很公开、反馈很快。你能看见他们怎么谋生、怎么学会东西、怎么试错、怎么被市场拒绝、怎么换方法，也能看见“后来成功”之前那些通常会被传奇删掉的几年。

## 我现在根本不知道自己以后要做什么

先读跨人物章节：

- [目标不是先想清楚的：先做一点，现实才开始回答你是谁](chapters/01-goals-are-made-not-found.md)

再读人物全文：

- [early id / DOOM](profiles/early-id-doom.md)
- [Gunpoint / Tom Francis](profiles/gunpoint.md)

这两篇共同反对一种很常见的倒写：

> 成功的人从小就知道自己的目标。

Romero、Carmack、Tom Francis 真正值得看的地方，是目标怎样在 **玩、拆、写、做、发表、被别人反馈** 的过程中越来越具体。

有些人不是先想明白人生，再开始行动。

而是先长期做某些事情，现实才逐渐告诉他：

> 这件事可能值得我把更大一部分人生放进去。

## 我喜欢游戏、技术、写作或别的东西，但不知道这算不算“正事”

先读：

- [early id / DOOM](profiles/early-id-doom.md)
- [Gunpoint / Tom Francis](profiles/gunpoint.md)

本书不会告诉你“兴趣一定有用”。

真正的问题是：

> **兴趣有没有发生转换？**

例如：

```text
喜欢
→ 比较
→ 拆解
→ 修改
→ 做出东西
→ 给陌生人看
→ 被现实反馈
→ 再修改
```

没有发生转换的爱好可以只是娱乐，这完全正常。

但一旦发生了转换，它就可能开始生成能力、作品集、判断力、合作者甚至职业入口。

## 我喜欢游戏，但家里不让我玩，也不相信做游戏是正经工作

先读两段真实的人生对照：

- [early id / DOOM：Romero 的家庭冲突、继父买电脑与职业形成](profiles/early-id-doom.md)；
- [第一章：目标不是先想清楚的](chapters/01-goals-are-made-not-found.md)。

有些家庭反对的是**玩游戏占用学习时间**，却欢迎学习编程、画画和写作；有些家庭允许游戏和作品，但不愿让你承担无保障的职业风险；也有家庭不理解，却尊重成年人的选择。它们对应完全不同的问题，不能只归结为“家长不支持”。

先分清你真正被限制的是：能否接触作品、能否亲自动手、能否公开获得反馈，还是已经成年后能否选择职业。**在没有第一份小作品、预算或真实市场证据以前，不要把“和家人对抗”错当成作品必然成功的证明。** 已成年并准备转行的人，还要独立核算工资、存款、住所、照护和再就业退路。

想进一步研究家庭控制如何让一部分潜在创作者**还没入行便从样本里消失**，进入 [中美代际与家庭门控研究](research-notes/family-gates-game-creator-us-china-027.md)。那里也保留支持/失败的反例和历史时效限制。

## 我很想辞职做自己的东西，但怕一押就是几年

先读跨人物章节：

- [先买几个月试错：做自己的事之前，先解决谁替你付时间](chapters/02-buy-time-before-betting-your-life.md)

再读人物全文：

- [FTL](profiles/ftl.md)
- [early id / DOOM](profiles/early-id-doom.md)

FTL 最值得看的不是 Kickstarter 募了多少钱，而是 Kickstarter **之前**：

> 职业能力  
> → 储蓄  
> → 有限几个月  
> → prototype  
> → 外部评审  
> → 更多证据  
> → 才逐渐加码。

early id 也不是先辞掉 Softdisk 再祈祷。

他们先在夜里做出东西，先让市场证明它能赚钱，再提高自己的风险暴露。

这两篇都在讲一个很朴素的原则：

> **不要为了证明决心，主动把一个本来可以便宜失败的问题变成昂贵失败。**

## 我没有很多钱，甚至必须一边活着一边做

先读跨人物章节：

- [先买几个月试错](chapters/02-buy-time-before-betting-your-life.md)

再读人物全文：

- [Kenshi](profiles/kenshi.md)
- [Rocket League](profiles/rocket-league.md)
- [FTL](profiles/ftl.md)

三条路线完全不同：

- Chris Hunt 用夜班工资购买个人开发时间；
- Psyonix 用 work-for-hire 购买整个公司的存续时间；
- FTL 两位创作者先用储蓄购买一个有限实验窗口。

所以“没融资”不是一个生产模式。

真正的问题是：

> **谁在替你支付继续试错的时间？**

有时候是老板，有时候是客户，有时候是储蓄，有时候是玩家。

## 我已经失败很多次了，是不是说明我不适合做这件事

先读跨人物章节：

- [失败不是资产：只有留下下一次还能使用的东西，失败才开始值钱](chapters/03-failure-only-matters-if-something-survives.md)

再读人物全文：

- [Bills Must Be Paid](profiles/bills-must-be-paid.md)
- [Rocket League](profiles/rocket-league.md)

失败当然可能只是失败。

本书不浪漫化它。

真正值得问的是：

> **失败以后留下了什么？**

可能留下：

- 更快的制作能力；
- 一个工具；
- 一段代码；
- 对某个平台的知识；
- 对某种用户反应的判断；
- 一个以后还能重新做的问题；
- 也可能什么都没留下。

《Bills Must Be Paid》最容易被误读成“七个月爆款”。

但那七个月压缩的是此前七年的高频制作和失败资本。

《Rocket League》则更极端：团队早在 2008 年就把“汽车踢球”做过一次。第一次没有得到后来的商业结果，但它没有因此变成零。

## 我总觉得别人有了新技术就无所不能，而自己是不是已经晚了

先读跨人物章节：

- [技术时代不会替你做选择：有人用现成工具，有人重组平台，有人自己造出窗口](chapters/04-technology-will-not-choose-for-you.md)

再深入：

- [early id / DOOM](profiles/early-id-doom.md)
- [Gunpoint / Tom Francis](profiles/gunpoint.md)
- [PLAYERUNKNOWN / Brendan Greene 研究档案](../cases/CASE-032-pubg-brendan-greene.md)
- [工业革命比较实验室](../cross-industry/industrial-revolutions/README.md)

DOOM 特别适合把技术决定论拆开。

Carmack 不是坐等 PC 发展到某个年份，然后领取一项“现在可以做 FPS”的时代福利。

他自己就在推进 renderer / engine 的技术前沿。

所以技术机会至少有三种：

- 有人继承已经扩散的工具；
- 有人把已有技术重新组合成新用途；
- 有人自己把技术边界向前推，给团队创造新窗口。

真正的问题从来不是：

> “新技术来了没有？”

而是：

> **它具体把什么变便宜了？谁真正能用？谁看见了新的可能？谁甚至亲手创造了那个可能？**

## 我做出来的东西明明不差，但不知道什么时候让市场进来

先读：

- [市场不是最后一步：有时玩家、钱和反馈在“做完之前”就已经进入生产系统](chapters/05-market-interface-is-production.md)

再深入：
- [Minecraft](../cases/CASE-014-minecraft.md)
- [Factorio](../cases/CASE-035-factorio-wube.md)
- [Bills Must Be Paid](profiles/bills-must-be-paid.md)
- [Brigador](../cases/CASE-026-brigador.md)

这组案例共同提醒：

> **有曝光，不等于市场接口有效；市场越早进入，也不等于越好。**

真正要先问的是：

> 我现在最怕判断错什么？需要的是玩法反馈、需求规模、产品可理解性，还是 runway？

而且这些方法高度依赖年份。2009 Minecraft、2013 Factorio、2016 Brigador、2026 Bills Must Be Paid 处在完全不同的平台环境里。

## 我已经成功过一次，为什么事情反而越来越复杂

这时先把“扩张”拆成两个问题：

> **我真的需要更多 capability，还是更需要保留不承诺的选择权？**

补读：
- [Into the Breach / Subset Games](../cases/CASE-020-into-the-breach.md) — 第一次成功以后，用 retained earnings 买低 burn、延迟公开和长期 prototype，而不是立刻把 FTL 成功固化成续作与更高 fixed cost；
- [thatgamecompany](../cases/CASE-057-thatgamecompany-vc-equity-expansion.md) — 另一条路径：用 equity 直接扩公司 capability，但同时进入 board / ownership / fundraising governance；
- [Zachtronics](../cases/CASE-051-zachtronics.md) + [Spiderweb Software](../cases/CASE-058-spiderweb-fit-lock-in.md) — 如果一种成功 grammar 已经积累多年，转型成本会怎样反过来变高。


先读：

- [early id / DOOM](profiles/early-id-doom.md)
- [Rocket League](profiles/rocket-league.md)

成功不是结局。

成功会买来：

- 更多钱；
- 更多人；
- 更高野心；
- 更多选择权。

也会带来：

- 组织冲突；
- 更高固定成本；
- 更复杂的决策权；
- “我们以后究竟要成为什么”的新问题。

early id 从 DOOM 到 Quake 的历史尤其说明：

> **解决“怎么做出来”之后，人生和组织会立刻出现下一道完全不同的题。**

# 如果只记住这套书的八句话

目前这批 Profile 最值得共同留下的，不是“辞职”“坚持”或“独立开发”本身。

而是：

1. **目标常常是做出来的，不是先想出来的。**
2. **兴趣只有发生转换，才会变成能力资本。**
3. **活下来本身是一项生产策略。**
4. **失败值不值钱，要看它有没有留下下一次还能使用的东西。**
5. **技术既可以被继承，也可以被重组，甚至可以被创作者自己向前推进。**
6. **市场不是最后一步；它可能很早就开始提供钱、反馈、误导和约束。**
7. **任何成功经验都有年份；机制可能耐久，具体平台打法会过期。**
8. **成功不是证明你找到了终极答案，而是给你换了一套更难的问题。**

## 关于“能不能照着做”

这不是保证回报的职业攻略，也不是“成功者做了什么，你照抄就能成功”。

每篇文章都会尽量区分：

- **可以迁移的机制**
- **只属于当事人的条件**
- **运气 / 右尾事件**
- **目前还不知道的事实**

所以这里所谓“人生性价比”，不是寻找一条稳赚的人生路线。

而是尽量让一个人在承担几年真实人生之前，先看见：

> **别人当年到底付了什么、拥有什么、错了什么，又在哪一步获得了继续下注的资格。**
