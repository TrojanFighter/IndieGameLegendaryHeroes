# Narrative Source Pack｜供非虚构作者独立选材的资料接口

> **Owner：Lane A 定义接口；Lane B 负责原始史实与补证；Lane C 资料编辑整理、冻结和交付中性 pack。** 属 [跨模型扩大试点](EDITORIAL-CROSS-MODEL-ROLLOUT-2026-10-09.md) 的辅助规范，不是 Evidence Ledger 的替代品、强制 schema 或新事实晋级流程。

## 目的：研究完整、作者自由、审稿严格

传统 Case 的「能力 / 现金流 / 团队 / 范围 / 失败 / 市场 / 判断」矩阵适合研究；将这套次序直接投喂写作模型，容易产出观点导向的案例综述。Narrative Source Pack 的目的不是换一种模板替 Case，而是把已核资料重新暴露为**可各自成立的真实事件、不同人物的表达、时间关系与可选择的不完整故事线**。只在确实进入人物或章节试写时创建 Pack；不对全库自动 backfill。

Pack 不是下一份 `claims.md`，不授权作者根据「戏剧合理性」发明动作、对话、心理或结果。所有关键材料仍可追到 canonical Evidence、精确来源和事实强度。

## Writer Pack 允许包含什么（尽量简短）

1. **冻结信息与范围。** `case_id / evidence_ledger_blob_sha / case_blob_sha / snapshot_ref / date`，说明 main 或未合并 PR 事实，具体历史区间和作者可选择的叙述焦点。
2. **事件清单（不预选起承转合）。** 每项：谁、在什么时候（已知粒度）、具体做了什么、当时能知道什么、可观察结果、`E-ID + 来源 URL`、归属类别（同期记录 / 本人多年后回忆 / 记者见闻 / 研究性解释）。按真实时间提供，不要求使用全部事件。
3. **人物与冲突的原话入口。** 只列真实可访问采访/日志的链接、说话人、年月、观点、专业用语／真正的自嘲。如果逐字引语未经回源核对，只写 **QUOTE_CANDIDATE / NOT VERIFIED FOR QUOTE**，不能把中文概述加引号；引文勿大量复制第三方受版权保护的文本。
4. **关系和不同见证。** 同伴、家人、雇主、协作者、发行商与作品中各自证实的职责；对时间、责任、动机有不同说法时并列而非挑选更好看的版本。
5. **时序与状态断点。** 哪些是计划、原型、售卖中、EA、发售、回顾，不能以最终结果倒推当时已知；关注者≠测试者≠购买者；资本到账≠可支出净预算。
6. **禁止补写 / 已知冲突。** 例如现场衣着、武器动作、当事人的未记录想法、家属心理、现金流精确额、团队总贡献人数、资料未记录的 bug 修复时点等。
7. **原始资料入口与反证。** 给独立作者完整的可阅读来源，而非「写作应该得出的理论」。若来源失效，诚实标明版本与可读范围。

可附一个简短的**读者可能需要知道的背景**，例如游戏机制和时代技术用人话解释；不要把它包装成作者论点。各 Pack 长度由证据丰度决定，不设字数门槛或“十条故事事件”门槛。

### 事件卡格式，仅作参考，不是统一电子表单

```text
日期/时段：2010-10-25
行动者：Tom Francis
真实材料：重新查看 Gunpoint 路线图，决定砍掉未实施的脚本演出计划
归属：本人同期开发日志（不是多年后的自我解释）
来源：CASE-007 / E008；完整原始链接
状态：PLANNED → REMOVED FROM PLAN
不得写：已经做出整套剧情又删除；当日已做成后来完整的 Crosslink
```

## 与 Fact-checker's Full Dossier 的严格区别

**Writer-facing Pack（对作者）：** 以事件和原话、时序、人物为中心。**不包含**其它 AI 的样稿、现有 Profile 全文、已经写好的开场建议、唯一「正确故事主线」、Thesis/Claim 结论清单，亦不包括解释成功率的市场因果定论。不同独立作者使用**相同 pack SHA** 和同样任务边界，可不使用 pack 的大部分材料。

**Fact-checker-facing Full Dossier（对事实审稿人）：** 允许获取完整 Case、Evidence、Claims、原始来源、所有候选、原正式稿、冲突记录和未知；逐句核实新增「动词、表情、情态、时态、因果、数字分母、说话态度」是否真的存在。不能以「作者有文学表达权」降低事实门槛。

**Editorial Decision（对主编）：** 可以结合思想表达和读者比较判断正文值得保留什么。编辑选择不会反向晋级为 canonical 研究真相。

## Lens 不等于写作提纲

面对 Kenshi，需要把「模拟城市连锁误判」中开发者真实讲出的动作和**最大的开发问题**都交付，而不能只给「涌现式世界很好玩」这一成功概念。必须保留口述语气和问题立场，不能凭想象加入「屋主拿起武器」「某年仍未修复此 bug」。

面对 Gunpoint，需要让作者看 2010 的计划裁切和 2013/2014 回顾的**分期区别**，而不是只给「品味能力 / 负向选择」概念。面对 Limit Theory，需要让作者看技术高光和取消时本人的困境，不能附上「技术完美主义毁了人生」的先验结论。

不同来源还有不同作用：一手日志可承担当时选择；回顾可承担作者后来的理解；二手传记擅长发现人物关系但不等于原始证词；同期评论可描述当时外界反应却不自动代表玩家总体。**同一事件既可重要，又可选择不写入最终叙事。**

## 材料就绪审查（只在拟写时，别给每个 Case 设强制通过分）

- 有无能核实「行动 + 后果」的具体事件，而不只有企业家观点？
- 有无至少两种时间立场：当时日志/报道 vs 后来回顾，或同时期不同参与者？若只有单一来源明确写缺口，不凑两种。
- 人物声音是否来自原文，而不是二手中文翻译叠加工整 AI 语句？
- 工作、亲密关系、劳动分工及家庭费用的细节是否可能损害当事人或缺乏独立来源？
- 有没有未成功、尚未成品或中途转向的记录，防止所有事件成为胜利前的必然铺垫？
- pack 是否已经含有「最终要证明……」或照着旧 profile 的段落摘要？如有，**删回来源状态**。
- 作者和审稿人能否分别读取不同层次的文件，而不发生 A/B 污染？

若只有结论而无关键行动，可以标记 `SOURCE_GAP` 后由 Lane B 定向调查，不必凑出开头场景。若来源只来自多年后自述，可以写严肃非虚构，但必须承认其回忆性质。

## 使用、版本与维护

- 推荐将小批量试验包保存于 `book/research-notes/narrative-source-pack-<subject>-<date>.md`，以日期与 snapshot/ref 冻结；这些是**衍生编辑资料**而非新的 canonical Case。新来源修改原 E-ID 后不要静默更新旧 pack，另记版本差异以便 A/B 复现。
- 文档版权和公共研究边界依然遵守仓库 AGENTS.md；不得放入另一个私人项目的人员、预算、设计或策略资料。避免因工具连接能读取私人内容就误作公开故事素材。
- 每包应能追溯到外部原始材料 URL；引文重用以具体说话人/原始文字为准，不能在本库把已有 AI 改写当作来源。
- 本接口不设提交时强制字段 lint，不通过空壳式全量迁移制造新负担；待多案例实践发现重复且可机械判定的缺陷，再考虑工具化。

## 试点初批建议

先做 **Gunpoint / early id / Limit Theory / GRIS** 四个覆盖范围不同的包，再做 FTL、Question 与 Chapter 06 的跨样本包。Kenshi 的既有试写源为 #292 和 `trial/kenshi-narrative-candidate-a-2026-10-09`，含 W0 中的事实漂移，需要先独立审校后再提供给作者。

**最后原则：资料整理者不得替写作者选出唯一能写的故事；写作者不得代替资料整理者证实事实。**
