# LR-005 — 成熟工业能力如何组成作者型团队：带走专业，不带走旧组织的题目

- Status: READER ROUTE / EVIDENCE-BOUNDED
- Last verified: 2026-10-07
- Best-fit: AAA / commercial game designer, gameplay programmer, producer, technical artist, QA lead, veteran cofounding an original-IP studio
- Core cases: CASE-061 Supergiant; CASE-062 Red Hook; CASE-059 Mega Crit; CASE-046 Sandfall; 王妙一/WILL
- Failure controls: CASE-048 The Magic Circle; CASE-054 Limit Theory; 月下/铸仙之境; CASE-056 Playdead

## 适用性限制：这个案例库不是同类员工的随机样本

以下人物因为成功、项目知名度、媒体采访与公开复盘而容易被研究者发现。他们证明某些生产组合 **可能奏效**，不告诉你一般大厂员工中有多少能做到，也不能据此预估个人成功率。

尤其 Red Hook、The Magic Circle 等公开失败/经济压力案例，同样经过可见性筛选，不能作为全体失败项目的随机对照。读者应将案例当作“风险与行动结构的参照”，而非“这种路径通常有效”的统计证明。

## 1. 何时进入

你已经知道自己或合作者拥有真实的工业执行能力，却不知道怎样变成自己拥有的产品题目，容易把旧组织的岗位与审批缩小复制为新公司。

如果没有独立 thesis，先做 LR-001 的身份/问题定义审计；如果有自己的 thesis，但不知道怎样重组技能、资金和决策权，走此路线。

## 2. 三次拆分

### 职位与能力

按实际作品核算：
- gameplay / engine / QA / telemetry；
- visual / technical art / animation；
- narrative / design / audio；
- producer / marketing / localization；
- taste / prior authorial artifacts / collaborators。

职位、名校、公司 logo 本身不等于能力证据；同样，退出大厂不意味着应丢掉工程纪律和质量标准。

### 作者与控制权

在雇佣/融资前弄清：
- 谁能改或杀掉核心 thesis？
- cofounder / investor / publisher 各拥有哪些 IP、里程碑、预算与创作 veto？
- 哪些过去成功的 benchmark 能直接进入新产品，哪些必须重新验证？
- 如果一个创始人退出，创作成果和股权如何处置？

### 能力与项目形状

每个 production obligation 都要对应到玩家价值，而不只是“正规项目应有”。
先问：
- 哪些体验必须依靠工业质量才能成立？
- 哪些美术/工具/流程只需够用？
- 缺失能力适合 cofounder、contractor、第三方工具还是删功能？
- 核心 loop 现在能让陌生玩家实际操作吗？

## 3. 最小验证实验

建议在充分遵守原雇佣合同、IP/保密约束的私人时间内，用 1–3 个核心成员做一个粗糙但完成交互闭环的 playable；让陌生玩家操作，并记录哪里理解、哪里失败、哪些反馈导致产品改变。

这不是统一的两周/四周指标。项目不同，最小证据形态不同；“只有短片”一般不能替代玩法验证，但 Red Hook 的 early teaser/email 能合法地验证市场可读性。

同时写一页：
1. 用户为什么玩、为什么回来；
2. 一次完整核心 loop 的实现成本；
3. 从 playable 到最小销售产品还缺哪几项能力；
4. 项目和 household 各能承受多少 burn；
5. 停止/转向/加人门槛。

## 4. 何时升级资源

| Evidence | 推荐动作 | 不要自动采取 |
|---|---|---|
| 只有理念 | 压缩原型、补自发学习与合作者 | 先建立完整工作室 |
| 可玩但理解率低 | 改 UX / core loop / thesis | 先花钱做电影宣传 |
| 陌生玩家主动复玩 | 验证市场与最低内容义务 | 直接套 AAA 对标 |
| 证明了受众但执行瓶颈具体 | 买缺失美术/QA/发行能力 | 按旧职级完整招聘 |
| 有付费信号且权利明确 | 核算 permanent burn 后再扩张 | 把融资等同 market fit |

## 5. 正反案例各说明什么

**CASE-059 Mega Crit**：Amazon QA 并未成为唯一身份来源；大学时期作者关系、卡牌品味和工作中的设计文档先于公司。它不是中国游戏制作人同岗对照。

**CASE-061 Supergiant**：EA 专业经验与同事关系可迁移，但没有照抄 EA 人员规模和授权流程；七人专业分工、低工资、创始人父亲提供场地、自有 IP 与发行商外围服务同时存在。

**CASE-062 Red Hook**：多年设计/美术/工程经验与独立作者性并存；与此同时孩子、房贷、个人储蓄/退休账户、早期借款、团队无薪和 Kickstarter/EA 一样真实。不能把筹款总额当作项目总成本。

**CASE-046 Sandfall**：Guillaume 任职时形成个人回合制 RPG 原型，找程序/美术互补作者，再创办公司；不是全工作室由 Ubisoft 人员组成。

**CASE-048 The Magic Circle**：真正离开 AAA 目标函数、具有高度作者性与 fit，也可能不够多用户购买。

**CASE-054 Limit Theory**：强技术可让技术进步持续快于产品闭合。

**CASE-056 Playdead**：共同创始人的能力互补需要支付股权、控制和长期关系协调成本。

## 6. “声望保全型变形”的取证边界

项目大不是自动错误；小也不是自动专业。只能在真实采访/项目时间线表明高规格、过早招聘或过度审批主要是为了保持名校/名企身份合法性，而非玩家/合同/市场约束时，才编码 Prestige-Preserving Distortion。

应优先排除：发行商验收、平台规范、受众最低美术门槛、创作者真实审美、必要的跨平台技术等竞争性解释。

## 7. 失败后还剩什么

记录 code、工具、受众、合作关系、可复用美术、作品信用、独立 IP 权利等 Failure Residue；同时记录现金、照护、家务、债务、健康与失去的市场机会成本。

“学到了很多”不能自动抵消净亏损。

## 8. 最小行动

把团队能力、独立 thesis、授权/控制权、两本现金账、第一轮陌生玩家反馈和明确 stop conditions 放到同一页。凡是新增岗位或高规格内容，都应指出它为哪一项已获得独立证据的玩家价值服务；否则先不要转成不可撤销的组织义务。
