# LR-003 — 房贷、育儿与高家庭支出的创作者：项目风险不能吞掉家庭现金流

- Status: READER ROUTE / EVIDENCE-BOUNDED
- Last verified: 2026-10-07
- Best-fit: married/partnered founders; children or dependents; rent/mortgage/debt; single-income households; caregiving constraints
- Core cases: CASE-042 The First Tree, CASE-004 Stardew Valley, CASE-015 Hollow Knight, CASE-036 Manor Lords; China household research 022
- Failure controls: 《奋斗吧！领主大人》, 《村与地下城》, 《贪婪大地》, CASE-037 Darkwood
- Boundary: 不把婚育作为能力高低指标；任何个体家庭条件未知则标 UNKNOWN，不推断真实私人情况。

## 1. 两本账：项目账和家庭账

**Project Ledger**：设备、软件、外包、税费、营销、QA、本地化、平台、法律、发行、开发者工资。

**Household Ledger**：净住房成本、日常生活、医疗/社保、孩子/长辈照护、债务、应急现金、伴侣收入变化、未计价家庭劳动、兼职可持续工时。

只有项目账户还有钱不够；必须知道家庭在项目失败时是否仍然安全。

## 2. 三种 runway 不能混为一谈

- **Financial Runway**：实际可自由调度资金 / 月度净现金消耗；区分 gross income 与税后、现金与锁定资产、一次性收入与可持续收入。
- **Time Runway**：稳定连续的制作小时，包括照护、通勤与家务后的真实剩余时间。一天“有四小时空闲”不等于四小时高质量开发。
- **Relationship / Labor Runway**：伴侣、朋友、合作成员是否同意长期承担额外家务、收入或无薪劳动；不能默认为无限供应。

三者可能分别成为最短板。尤其 **家人支持 ≠ 家人能够无限期承担成本**。

## 3. 家庭风险边界

| 问题 | 应明确的现实条件 | 失败信号 |
|---|---|---|
| 月度消耗 | household essential burn + project committed burn | 只算办公室和工资 |
| 收入冲击 | 伴侣收入/合同中断压力情景 | 只算正常月份 |
| 紧急备用 | 不受项目调用的生活及医疗应急金 | 用应急金维持迭代 |
| 照护时间 | 每周可持续有效工时与代偿成本 | 靠伴侣无偿加班遮蔽 |
| 团队责任 | 有薪/无薪、退出条款、预期里程碑 | 以理想要求无限忍耐 |
| 停止条件 | 约定现金下限、日期和下一轮证据门槛 | runway 每次耗尽再延长 |
| 回撤方案 | 复工、接单、恢复全职与家庭安排 | 把失败等同人生彻底失败 |

**不要给所有家庭一个统一的“至少储蓄 12 个月”标准。** 不同城市、家庭人数、债务与医疗制度使相同储蓄的实际承受力不可比。

## 4. 与项目设计相连：缩减义务，不只是压缩内容

真正的独立项目缩放不是“同一 AAA 游戏少做一点”，而是变动生产函数：

- 把视觉/写作强项放到产品核心，减少每单位玩家价值所需资产：The First Tree。
- 先制作 solo 可完成的闭环，暂时不用承担 multiplayer、UGC、持续运营义务。
- 买回作者连续时间而非先养团队：Manor Lords 从自由职业过渡到社区资助/Grant。
- 用已验证能力以外的外围服务替代永久雇佣：porting、QA、localization、发行。

一个可选 test 是：如果在总可用工时减半、融资不到账、伴侣不能继续额外承担家务的情况下，项目还能否降规格交付可玩体验？

## 5. 中外案例如何使用

- **The First Tree**：有全职工作和育儿责任，把短时长视觉叙事/现成资源当成 scope 结构；但不能据此猜他的家庭现金收入。
- **Stardew Valley / Hollow Knight**：伴侣收入、储蓄、生活成本和合作劳动构成真实 runway；游戏 headline budget 不是完整成本。
- **《贪婪大地》**：访谈明确涉及房贷、育儿、保姆与配偶收入冲击；同时发生从大项目缩成 solo top-down shooter 的 scope response。不能把访谈中的某年生活开支套到其他家庭。
- **《奋斗吧！领主大人》**：储蓄、低薪团队、成员离开、工作室关闭、恢复程序员工作形成明确的失败回撤路径。
- **《伏龙记》**：作者本人意识到配偶承担照护和家务，不可把这类劳动从“solo hero”传记中抹掉。
- **Darkwood**：众筹目标达成后 net runway 仍算错，是“拿到钱 ≠ 已覆盖长期 obligations”的预算反例。

## 6. 什么时候增加不可逆承诺

只有当项目核心 loop 经外部验证，且新增投入能**具体关闭已知瓶颈**，才考虑：
- 辞职；
- 固定办公场所；
- permanent hire；
- 个人借贷；
- 多年预定制作计划。

优先使用可撤回或可暂停的方案。家庭财务不得为了维持开发者身份而无限兜底。

## 7. 失败后的资产回收

项目停止时仍可保留代码、工具、试玩结果、观众、合作网络与经验；但应把它们视作 **Failure Residue**，不能把账面亏损自动包装为“能力投资有回报”。

重要的是能清楚回答：
> 这笔投入让下一轮什么事情真正变得更便宜、更可验证？

## 8. 最小行动

把 household burn 与 project burn 分账，建立可持续每周制作时间表，确认一次最小陌生玩家测试；在形成连续证据前，保护可回撤的收入能力，避免把伴侣与合作者的无偿劳动当成免费 runway。
