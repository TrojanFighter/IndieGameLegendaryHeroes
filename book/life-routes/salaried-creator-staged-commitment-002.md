# LR-002 — 有稳定工资的创作者：先购买证据，再购买自由

- Status: READER ROUTE / EVIDENCE-BOUNDED
- Last verified: 2026-10-07
- Best-fit: employed programmer / designer / analyst / QA / technical artist with small-project ambition
- Core cases: CASE-007 Gunpoint, CASE-059 Slay the Spire, CASE-014 Minecraft, CASE-042 The First Tree, CASE-053 Kenny Sun
- Failure controls: CASE-054 Limit Theory, CASE-037 Darkwood
- Boundary: 本路线不鼓励违反雇佣合同、竞业、保密或 IP/side-project 规则；不是财务/法律意见。

## 1. 先诊断：究竟是什么卡住你

工资支持生活和探索，也占用制作时间。判断是否减少雇佣工作，先说明多出来的时间要用于解决什么，以及这项变化会增加多少现金和家庭负担。

以下四种约束需要分别处理，不能都用“没时间”概括：

- **问题未清楚**：还说不清想验证哪种体验。先把问题缩到可以试做和否决的范围，再估算所需时间。
- **能力不足**：缺少美术、程序或产品判断。增加时间以后，仍需比较学习、缩范围与找合作者的代价。
- **反馈不足**：已有可玩版本，却缺陌生玩家及有效市场接口。下一步应让外部反馈进入判断，避免更长时间只靠自己确认。
- **连续时间不足**：已有产品假设的测试依据，后续劳动难以碎片化。把这种瓶颈具体记下来，再比较全职与保留工资的机会成本。

## 2. 最小实验：两道门而非直接辞职

### Gate A — 作者性与 playable

在合法的私人时间、私人设备和清晰 IP 边界内，产出一个核心行为闭环。它可以很丑，但必须让陌生人**实际操作**，而不是只看预告。

把这次试验留下的记录写清：
- 独立定义的一个问题；
- 玩家能够完成的最小操作循环；
- 一次陌生用户测试；
- 用户是否理解，是否愿意再玩；
- 哪个假设因此被推翻；
- 每周能稳定用于制作的有效小时数。

### Gate B — 证据与承诺升级

试玩显示体验有价值、市场有可辨认的受众，当前工作又造成可测量的制作瓶颈时，再比较增加投入的几种办法：
- 一段明确边界的休假；
- 降工时/合同工作；
- 找互补合作者；
- 发行商支持或补助；
- 最后才是辞职。

愿望单没有适用于所有项目的统一门槛。社交、叙事、战斗手感与复杂系统各需要能检验自身体验的办法。

## 3. Quit Decision Sheet

| 条件 | 应记录的可验证状态 | 不满足时 |
|---|---|---|
| 作品主张 | 一句话描述玩家获得的独特体验 | 缩到可测试问题 |
| 可玩版本 | 陌生人完成核心动作 | 做更小原型 |
| 外部检验 | 至少一项导致团队改变的外部反馈 | 重设计测试 |
| 时间瓶颈 | 在保留工资状态下明确观察到停滞原因 | 不先辞职 |
| 家庭承受期 | 按净现金、租房/房贷、家庭责任计算的承受期 | 降低固定成本 |
| 回撤选择 | 恢复就业/兼职/外包的实际方案 | 缩短下注期 |
| 停止条件 | 日期或现金下限触发停止、转向或恢复工作 | 先写止损 |

填完后，应能回答：辞职买来的时间将解决哪项已经识别的不确定性？再核对家庭承受期、回撤选择与停止条件，存款数不能单独替你做这个决定。

## 4. 为什么历史案例不等于今天的配方

Tom Francis 与 Kenny Sun 都在职业工作之外制作个人游戏，但转为全职的依据和时点不同。Francis 在《Gunpoint》首发周销售越过事先设定的阈值时已处于休假，随后辞去 PC Gamer 工作，没有返回原岗位。Sun 则在 Harmonix 工作期间持续做周末项目，按他2023年的回顾，这些作品收入最终能覆盖生活，他才于2018年转为全职独立。两者的工资、储蓄和具体生活成本都没有完整账本，不能把他们的阈值换成所有人通用的数字。

《Minecraft》把收入验证放得更早：2009年公开版本与六月开始的付费Alpha，让销售和反馈在制作中进入；Persson 后来回忆自己计算过离开日职的日销量阈值。这种收费形态与作品有关，他也明确说过，不适合所有项目，尤其不能不加检验地搬到某些重叙事游戏。

合作团队的承诺还可以不同时增加。《Slay the Spire》的 Casey Yano 先离开 Amazon，做出并测试原型后，Anthony Giovannetti 才离开自己的工作。两人的共同业余作品经历早于雇佣工作，不能把这个顺序写成“所有人都应试玩通过后才辞职”，或把Amazon经历本身当作创业能力保证。

保留全职工作也不一定要等到辞职才算完成一条路线。Wehle 在《The First Tree》制作期保留技术美术工作，通过较短范围、工具和授权素材组织视觉叙事作品，育儿责任则继续限制可用时间。Sun 的《Mr. Sun's Hatbox》更提供了停下来的选择：2016年的原型因范围超出当时业余时间而被搁置，2019年生产条件改变后才重启。工资之外的创作可以继续、缩小或暂放，不必只有越来越加码一种节奏。

外部资金同样不能省略完成与成本检查。《Limit Theory》的众筹没有保证交付；《Darkwood》后来完成了作品，但开发者回顾，众筹的税费、授权、硬件和奖励履约等支出减少了可用现金，资金不到十二个月就耗尽。Early Access 又延长了生存期，同时伴随后续范围扩大。筹到钱、有人关注与能够按预算收尾，需要分别验证。

这些材料覆盖2009年付费Alpha及2010年代的业余开发、发行和众筹环境。到2026年，保留的是用测试、收入与实际生产瓶颈判断承诺的机制；当年的平台曝光、融资机会、生活成本和再就业条件仍须重新核算。来源分别见 [Gunpoint](../../evidence/CASE-007-gunpoint-source-ledger.md)、[Minecraft](../../evidence/CASE-014-minecraft-source-ledger.md)、[Kenny Sun](../../evidence/CASE-053-kenny-sun-source-ledger.md)、[Mega Crit](../../evidence/CASE-059-slay-the-spire-mega-crit-source-ledger.md)、[The First Tree](../../evidence/CASE-042-the-first-tree-source-ledger.md)、[Limit Theory](../../evidence/CASE-054-limit-theory-source-ledger.md) 与 [Darkwood](../../evidence/CASE-037-darkwood-source-ledger.md) 的账本。

## 5. 严禁的推断

- 有工资就一定有业余时间；
- 没家庭负担就该辞职；
- 作品得到正面评价就已拥有足够支撑项目的市场需求；
- 一次原型好玩就证明全项目能交付；
- 有大厂经历就能复制 Mega Crit 的测试与数据分析能力；
- 工资职业与作者身份不能共存。

## 6. 最小行动

在雇佣合同与IP边界清楚的前提下，先做能让陌生玩家实际操作、也能否决核心假设的版本。记录每周有效产出、玩家行为和现金支出，用这些记录决定下一步是缩范围、找反馈、暂停，还是增加投入。工资可以支持这段探索，但不会自动提供业余时间，也不会保证失败代价很低；生活承受期与退出方案仍需单独核算。
