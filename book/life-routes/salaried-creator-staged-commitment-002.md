# LR-002 — 有稳定工资的创作者：先购买证据，再购买自由

- Status: READER ROUTE / EVIDENCE-BOUNDED
- Last verified: 2026-10-07
- Best-fit: employed programmer / designer / analyst / QA / technical artist with small-project ambition
- Core cases: CASE-007 Gunpoint, CASE-059 Slay the Spire, CASE-014 Minecraft, CASE-042 The First Tree, CASE-053 Kenny Sun
- Failure controls: CASE-054 Limit Theory, CASE-037 Darkwood
- Boundary: 本路线不鼓励违反雇佣合同、竞业、保密或 IP/side-project 规则；不是财务/法律意见。

## 1. 先诊断：究竟是什么卡住你

工资既占用时间，也购买探索期。只有当项目最短板确实是连续开发时间时，辞职才可能改善问题。

把约束分成四种：
- **Problem gap**：没有清楚想验证什么；增加开发时间只增加不确定探索量。
- **Capability gap**：缺美术/程序/产品判断；辞职不自动获得缺失能力。
- **Feedback gap**：已有 playable，但没有陌生玩家及有效市场接口；辞职只是更长时间的自我确认。
- **Time gap**：已验证产品假设，且缺少不可碎片化的连续劳动；此时才比较 full-time 与保留工资的机会成本。

## 2. 最小实验：两道门而非直接辞职

### Gate A — 作者性与 playable

在合法的私人时间、私人设备和清晰 IP 边界内，产出一个核心行为闭环。它可以很丑，但必须让陌生人**实际操作**，而不是只看预告。

记录：
- 独立定义的一个问题；
- 核心操作最小 loop；
- 一次陌生用户测试；
- 用户是否理解，是否愿意再玩；
- 哪个假设因此被推翻；
- 创作者每周可稳定支出的有效小时数。

### Gate B — 证据与承诺升级

只有当试玩显示有价值、市场有可辨认受众、且当前工作造成可测量的生产瓶颈，才考虑：
- 一段明确边界的休假；
- 降工时/合同工作；
- 找互补合作者；
- publisher/grant；
- 最后才是辞职。

不要要求所有项目都达到相同 wishlist 数字；社交、叙事、战斗手感、复杂系统需要不同验证方式。

## 3. Quit Decision Sheet

| 条件 | 应记录的可验证状态 | 不满足时 |
|---|---|---|
| Thesis | 一句话描述玩家获得的独特体验 | 缩到可测试问题 |
| Playable | 陌生人完成核心动作 | 做更小原型 |
| Reality | 至少一项导致团队改变的外部反馈 | 重设计测试 |
| Time bottleneck | 在保留工资状态下明确观察到停滞原因 | 不先辞职 |
| Household runway | 按净现金、租房/房贷、家庭责任计算的承受期 | 降低固定成本 |
| Exit option | 恢复就业/兼职/外包的实际方案 | 缩短下注期 |
| Stop rule | 日期或现金下限触发 kill/pivot/return | 先写止损 |

**Quit Threshold 不是固定存款数，而是“辞职买来的时间会关闭哪个已识别的不确定性”。**

## 4. 为什么历史案例不等于今天的配方

- **Gunpoint**：Tom Francis 维持 PC Gamer 工资、夜晚做 GameMaker、经过测试/公开沟通，销售超过事先设定的阈值才转职业身份。可迁移的是 staged commitment，不是“任何人都应该夜间开发三年”。
- **Slay the Spire**：Casey Yano 从 Amazon QA 离开后先与 Anthony 做 prototype；Anthony 直到 playable test 之后才退出工作。作者线程与合作关系早于两人的雇佣经历。不能把它误写成“所有 Amazon 员工都适合创业”。
- **Minecraft**：保留职业收入，同时 paid Alpha 接上反馈/融资，直到产品收入出现辞职依据；2009 年具体 alpha 市场条件已过时。
- **The First Tree**：技术美术型创作者保留全职工作，用现成工具/资产把项目变形成可承受的视觉叙事作品；已有育儿责任使时间尤其稀缺。
- **Kenny Sun**：多款周末项目形成 shipping 与商业能力，作品收入足以覆盖生活后才转独立。不是一次性辞职豪赌。
- **Limit Theory / Darkwood**：众筹/项目热度不等于完成能力或净可用资金；原型之外仍有 closure、预算和工期风险。

## 5. 严禁的推断

- 有工资就一定有业余时间；
- 没家庭负担就该辞职；
- 作品得到正面评价就已拥有足够 market sufficiency；
- 一次 prototype 好玩就证明全项目能交付；
- 有大厂经历就能复制 Mega Crit 的 QA/data 能力；
- 工资职业与作者身份不能共存。

## 6. 最小行动

先完成一个不需要外部批准、能被陌生玩家否决的 playable；记录每周有效产出、玩家行为、现金 burn，再由 evidence 决定下一次承诺。项目未成立时，工资不是敌人，而是保证失败可以便宜发生的一种资本。
