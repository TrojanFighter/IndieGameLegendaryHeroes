## 0. 本轮只补三个缺口

021 留下三个明确缺口：

1. 教育层：缺一个高能力、高自主、长期自驱，但仍因产品判断/范围闭合失败的强商业案例；
2. 行业层：缺一个成熟老兵确实卸载旧 AAA objective function，却仍被市场否决的案例；
3. 社会层：中国采访缺 household economics，导致“家人支持/反对”被写得过度心理化。

本轮不继续发明概念，只把这三格补实。

# 一、教育层强失败控制：Limit Theory

参见：
- `cases/CASE-054-limit-theory-fit-trap.md`

## 1.1 为什么它比“自由教育失败”更有价值

Josh Parnell 不是：

- 缺教育；
- 缺技术；
- 缺自主性；
- 缺市场兴趣。

相反，他具备：

- Stanford CS / computer graphics 背景；
- 极强的 graphics / engine / procedural systems 能力；
- 完全自主的项目 ownership；
- Kickstarter 明确市场兴趣；
- 长期公开 devlog / prototype / community；
- 六年持续投入。

最后项目仍取消。

因此它直接封死一个错误叙事：

> **只要摆脱外部标准答案、足够聪明、足够自由，就会自然形成好产品。**

## 1.2 真正失败的是“强能力不断把问题吸向自己”

Limit Theory 最重要的结构不是：

> scope 太大。

而是：

```text
graphics / engine / procedural simulation 强
→ 项目不断把更多难题定义成 engine / systems 问题
→ custom engine
→ custom scripting language
→ procedural economy / AI / UI / modding
→ engine rewrite / architecture generation
→ high-entity-count demo
→ engine 越来越成熟
→ complete game 仍然很远
```

2018 取消时，Parnell 自己承认：

- 离 feature completion 仍然非常远；
- engine 是相当 solid 的 engineering；
- game-side Lua code 明显没达到同等成熟度。

所以：

> **局部能力资本持续升值，可以与整体产品进度脱钩。**

## 1.3 对教育层的修正

教育层以后不能只问：

> 你会不会自己学？  
> 你会不会自己出题？

还要问：

> **你最强的能力会不会把所有问题都改写成它喜欢解决的形状？**

因此新增一个教育/能力审计：

### Capability Capture Risk

- 我是否不断选择能证明自己最强能力的任务？
- 我的技术/美术/叙事进步，是否同步推动玩家产品闭合？
- 我是否因为“这个问题很有趣”而把它误判为“这个问题现在值得解决”？
- 哪个 product obligation 已经明显落后于我的 specialist frontier？

Limit Theory 说明：

> **Problem Ownership 也需要被 Scope Judgment 和 Product Closure 约束。**

# 二、行业层最重要的失败控制：The Magic Circle

参见：
- `cases/CASE-048-the-magic-circle.md`

## 2.1 这不是“AAA 老兵没卸载旧函数”

Question 的核心成员拥有 BioShock / Thief / Dishonored / Deus Ex 等 immersive-sim 前史。

但这个项目恰恰不是：

> 把 AAA 缩小做一遍。

他们主动选择：

- 三人高信任核心；
- 极少共识流程；
- 强 authorial voice；
- meta-development 题材；
- 玩家直接编辑 NPC 规则和 AI；
- Early Access 做公开 QA / compatibility；
- 明确反感旧 AAA process-heavy 文化。

也就是说：

> **objective-function rewrite 本身是成立的。**

这正是我们此前一直缺的反压力：

> 老兵完成 deliberate unlearning，仍然可以失败。

## 2.2 项目 fit 甚至非常强

The Magic Circle 高度贴合三位核心成员：

- Jordan Thomas：immersive-sim design / narrative / directing；
- Stephen Alexander：VFX / narrative art / BioShock production memory；
- Kain Shin：AI / gameplay programming。

题材也是他们最熟悉的：

> development hell / designer–player relationship / unfinished game culture。

因此它不是 Creator–Project Fit 不足。

相反：

> **这个项目几乎“只有这几个人才会这样做”。**

## 2.3 但 fit 不能解决 category / audience / market access

现有 case evidence 支持：

- 产品高度独特；
- immersive-sim / meta-game 本身属于 niche-within-niche；
- category legibility 弱；
- 团队几乎没有 marketing budget；
- 销售不足以长期维持团队。

所以：

> **Capability Fit ≠ Market Sufficiency。**

这恰好给“成功卸载旧函数”加上一条非常重要的边界：

```text
AAA objective function successfully discarded
+
creator–project fit strong
+
authorial ownership high
≠
commercially sufficient audience
```

## 2.4 行业层因此必须增加 Market Legibility Audit

以后 deliberate unlearning 成功后仍要问：

- 玩家能不能一眼理解“这是什么”？
- 它属于哪个购买场景？
- existing audience 是否足以覆盖成本？
- 项目强项是否能形成 trailer / demo / store-page legibility？
- 团队是否错误假设“质量好 → 媒体/Steam自然发现”？
- niche 内部是否还进一步 niche 化？

所以：

> **去掉旧答案，只是恢复重新出题的权利。**
>
> **市场仍有权回答：这个题不值得足够多人付钱。**

# 三、中国独立开发 household economics：把“家人支持”拆成现金流

这一块此前材料太薄。

中国公开采访常压缩成：

> 辞职追梦；  
> 家人支持；  
> 咬牙坚持。

但真正决定 Exploration Survival Time 的是：

- savings；
- mortgage；
- spouse income；
- childcare；
- parental housing；
- monthly burn；
- unpaid collaborators；
- reemployment option。

以下四个案例足以建立第一版字段。

---

## 3.1 《奋斗吧！领主大人》：婚后、几乎全部积蓄、100 万投入、失败后回就业

GameRes 采访记录：

- 制作人饭夫俗士此前是新浪微博后端程序员；
- 2016 年刚结婚；
- 拿出几乎全部积蓄，并和朋友凑约 100 万成立工作室；
- 自己不拿工资，团队工资远低于行业平均；
- 策划成员因经济压力在 2017 年底回去找工作；
- 2018 年中资金链断裂，工作室解散；
- 游戏 Steam 首发约 400 多套，半月勉强过千；
- 制作人后来重新找程序员工作，利用双休继续更新；
- 妻子一直支持，但本人明确提到结婚、生育计划、父母年龄等带来的压力。

Source:
- GameRes，《〈奋斗吧！领主大人〉制作者：独立游戏是熬出来的》  
  https://www.gameres.com/829400.html

### 价值

这是一个非常完整的：

```text
Savings
→ Team payroll
→ Revenue shortfall
→ Team member exit
→ Studio dissolution
→ Founder reemployment
```

案例。

它说明：

> **家庭规范支持可以很高，但 household risk capacity 仍然有限。**

同时：

> **Reemployment Option 本身是重要 survival asset。**

---

## 3.2 《贪婪大地》：房贷 + 保姆 + 孩子 + 配偶失业，把项目成本推到家庭系统里

机核 2025 长篇采访提供了罕见的家庭现金流细节：

- 制作人老V原本是程序员；
- 2022 年尝试组团队；
- 一度获得 25 万个人投资，但投资人一个月后资金链断裂；
- 团队还没正式入职即解散；
- 后来改为 solo；
- 项目原本想做更大的刷宝游戏，单人条件下主动缩成类 Vampire Survivors / top-down shooter；
- 家庭每月支出接近 3 万；
- 房贷约 1.5 万；
- 保姆费 6000+；
- 配偶在双减后失业，同时怀孕；
- 创业与育儿/家务冲突造成持续家庭矛盾；
- 2023 年游民星空提供预付和 UI 支持，成为新的 runway 节点。

Source:
- 机核，《独立游戏人的老婆："我在历劫"——贪婪大地一个人开发的游戏》，2025  
  https://www.gcores.com/articles/193396

### 价值

这直接说明：

> **项目 burn 不能只算公司账户。**

真实 burn 是：

```text
项目成本
+
房贷
+
育儿
+
保姆
+
配偶收入变化
+
家庭劳动
```

同时它提供一个很清楚的 scope response：

> household burn 上升 + external funding collapse  
> → 大项目缩成 solo 可承受形态。

这是真正的 Capability-shaped Scope 与 Household Economics 接口。

---

## 3.3 《村与地下城》：有储蓄、伴侣支持，但现金只出不进仍形成巨大压力

制作人“村长”2025 第一人称文章：

- 30 多岁；
- 已婚有孩子；
- 原本收入不错、做到公司高层；
- 攒了一些钱后裸辞；
- 自学代码半年；
- 妻子与朋友支持；
- 妻子还参与像素化美术；
- 但妻子当时没有工作、孩子仍在读书；
- 裸辞一年后，即使有储蓄，看着资金持续流出、没有收入，心理压力仍非常大。

Source:
- GameRes，《写代码累了，想聊下独立游戏制作人到底是个什么心理状态》，2025  
  https://www.gameres.com/911828.html

### 价值

这提醒：

> **Savings ≠ 安全感。**

同样一笔存款，在：

- 单身；
- 配偶有收入；
- 配偶无收入；
- 有孩子；

四种情况下完全不是同一 runway。

因此以后不能只记录：

> “有 N 个月储蓄。”

还要记录：

> **Household Dependency Ratio。**

---

## 3.4 《伏龙记》：配偶支持也意味着配偶承担了隐形劳动与机会成本

《伏龙记》制作人在上线前文章中明确写：

- 创业已经 3 年；
- 妻子长期支持其做自己想做的游戏；
- 女儿出生后，妻子承担了更多家庭责任；
- 他事后反思自己过去只看到“做游戏辛苦”，却低估了创业者妻子和母亲承担的成本。

Source:
- 机核，《伏龙，有悔｜在〈伏龙记〉上线前夕，我不想谈游戏》，2018  
  https://www.gcores.com/articles/95962

### 价值

这里暴露一个独立开发史经常漏掉的生产输入：

> **Unpaid Domestic Labor。**

如果伴侣承担：

- childcare；
- household management；
- emotional labor；
- income stabilization；

那么“solo dev / founder sacrifice”并不是完整成本账本。

# 四、Household Economics 应正式进入 Creator Profile

从现在起，能取得资料时新增：

## Household Structure
- relationship / marriage；
- children；
- parents / elder-care obligations；
- housing situation。

## Cash Runway
- savings；
- spouse/partner income；
- founder salary；
- mortgage/rent；
- childcare；
- other debt。

## Hidden Labor
- childcare allocation；
- domestic labor；
- partner participation in art / QA / admin；
- emotional / logistical support。

## Exit / Recovery
- prior profession；
- reemployment ability；
- severance；
- social insurance；
- whether studio failure means household insolvency。

## Team Spillover
- unpaid teammates；
- below-market wages；
- friends/family contributors；
- who exits first when runway compresses。

这比“家人支持 YES/NO”有解释力得多。

4. Reality Adjudication；

022 再要求记录两个横向风险：

### Capability Capture Risk
> 最强能力是否不断把项目吸向它最喜欢的问题，而非最需要解决的问题？

> 即便作品成立，它是否足够可理解、可定位，并拥有能覆盖成本的受众？

- Limit Theory；

# 七、对“英雄为什么没有出发”的更完整回答

到现在，失败至少可以发生在七个不同节点：

```text
1. 没有 Problem Ownership
→ 永远解别人出的题

2. 有 Ownership，没有 Judgment
→ 自由地做坏题

3. Judgment 尚可，没有 Cheap Prototype
→ 错误暴露太晚

4. Prototype 有了，没有 Reality Adjudication
→ 自嗨

5. Feedback 有了，没有 Survival Time
→ 正确方向也活不下来

6. 核心成立，没有 Capability Scaling
→ 永远只能手搓

7. 产品成立，没有 Market Sufficiency
→ 好作品仍养不活组织
```

而第 8 种失败来自能力本身：

```text
8. Strong Capability captures the project
→ 局部越来越强
→ 整体越来越不闭合
```

所以：

> **英雄没有出发，不一定是被社会拦住。**
>
> 有时他已经出发、非常自由、非常聪明，甚至一路做出了大量漂亮东西，但始终没有走向一个能够完成和被购买的产品。

这必须成为 reader-facing 章节的重要反浪漫化部分。
