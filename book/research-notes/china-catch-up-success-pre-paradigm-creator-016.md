## 0. 研究问题

当前中国独立游戏研究已经能证明：

- 商业游戏/大厂经历可以提供强 capability capital；
- 同一经历也可能绑定特定 objective function、benchmark 和组织习惯；
- 小团队 0→1 与成熟组织 1→100 的能力要求并不相同。

本笔记继续追问：

> **为什么一个社会能够高效生产大量高能力从业者，却仍可能让其中很多人更擅长完成“上一版本已经知道的问题”，而不是定义下一版本的问题？**

这不是“中国人不创新”的问题。

更精确的是：

> **追赶阶段的高回报能力，什么时候会在前沿阶段变成能力陷阱？**

## 1. Catch-up Success Imprinting｜追赶成功烙印

工作定义：

> 当个人、组织或一代从业者长期因“识别先进标准 → 学会 → 复制 → 工程化 → 规模执行”获得真实高回报，这套策略会被内化成一般世界规律；当产业逐渐接近前沿后，旧评价函数仍可能继续决定招聘、晋升、立项和人生建议。

基本链条：

```text
外部成熟答案很多
→ 学习/模仿/工业化回报极高
→ 成功者获得职位、财富与解释权
→ “别人已经证明什么值得做”成为默认问题清单
→ 产业逐渐接近前沿
→ 可抄答案减少
→ 但旧成功函数继续筛选人才和项目
→ exploration / reframing / problem ownership 被低估
```

这与一般 success trap 相邻，但作用单位可以跨越家庭、学校、公司与产业发展阶段。

## 2. “春登”不是年龄：Success-Path Version Lock

`春登`只保留为内部 H-layer 标签。

这里更正式的表达是：

> **Success-Path Version Lock / 成功路径版本锁定**

一个人不需要年长，也不需要中国身份，就可能出现同一结构：

- 长期在成熟 AAA pipeline 中成功；
- 长期依赖成熟手游/F2P objective function；
- 长期通过 benchmark、名企履历和标准流程获得奖励；
- 因而把“我曾经成功的生产制度”误当成“做产品本身的普遍规律”。

因此：

> **“春登”不是年龄，而是成功经验没有版本号。**

这也解释为什么：

- 欧美 AAA 老兵可以出现相同问题；
- 中国年轻开发者也可以很早完成 benchmark lock-in；
- 老开发者仍然可以保持高 problem ownership。

## 3. Production Capital ≠ Problem-Framing Capital

### Production Capital

回答：

> **一个已经知道大致要做什么的东西，怎样可靠地做出来？**

包括工程、pipeline、QA、schedule、大团队协作、性能、工具、内容生产与上线运营。

### Problem-Framing / Exploration Capital

回答：

> **下一件值得做的东西到底是什么？我们凭什么知道？**

包括：

- 自己定义问题；
- 发现异常现象；
- 保留多个 competing hypotheses；
- cheap prototype；
- 第一版允许粗糙；
- 失败后迅速改模型；
- Creator–Project Fit；
- 没有成熟 genre/benchmark 时仍能建立现实校验。

正式研究必须拒绝：

> AAA / 名企 / 名校 / 海外履历 = 原创能力

这些履历首先证明 Production Capital。

它们只有在当事人确实拥有 project-framing authority、prototype authority、market/problem contact 时，才进一步证明 Problem-Framing Capital。

## 4. Pre-paradigm Creator｜前范式创作者

“农民发明家”只作 H-layer 比喻。

正式工作定义：

> **在还不存在成熟范式、可靠 benchmark 或明确赛道的问题上，通过低成本直接实验取得第一手现实反馈的创作者。**

典型结构：

```text
成熟组织：
Genre → Feature Checklist → Production → Market

前范式创作者：
Phenomenon → Cheap Prototype → Reality Feedback → Iteration → Category Emerges
```

关键不是“外行更聪明”，而是：

- 没有足够资源让错误方向长期续命；
- 没有成熟答案可以直接复制；
- 必须更早接触现实；
- 项目往往围绕自身能力限制重新设计；
- 类型名称常常在作品出现以后才由市场补上。

### 已有案例接口

- early id / Carmack：技术能力直接创造新设计可行域；
- Gunpoint / Tom Francis：长期比较与 taste 进入 prototype；
- The First Tree：Capability–Project Fit；
- PLAYERUNKNOWN：已有 substrate 上重组规则；
- Zachtronics：能力与产品语法长期高度匹配，同时提供 FIT-LOCK-IN 反压力；
- NExT / 中国商业游戏转作者研究：检验高 Production Capital 是否同时拥有 0→1 问题定义权。

## 5. Capitalized Error Persistence｜资本化错误续命

大资源的双刃剑：

```text
Prestige / AAA履历
→ 更容易取得大预算
→ 高 scope / 重资产 / 长周期
→ sunk-cost 与组织承诺增加
→ 核心 product thesis 更晚接受市场裁决
```

因此：

> **资本和工业能力不仅能帮助好创意成长，也能延长坏假设的寿命。**

这并不意味着“小团队一定更对”。

真正值得比较的是：

> **Time-to-Player-Truth / Time-to-Reality-Truth**

而不是团队大小。

## 6. “创新要练”：吸收能力与生成能力不是同一个函数

工作假说：

> 标准化教育和成熟组织训练可以非常有效地扩大 absorptive capacity：快速理解、掌握、执行已经存在的复杂知识；但未必同步训练 Generative Agency、Problem Framing 和开放问题下的实验判断。

因此问题不是：

> “做题能力和创新能力无关”

而是：

> **Selection Function Mismatch / 选拔函数错配**

追赶阶段，学现成答案、工程化、复制、质量提升本来就是高收益能力。

接近前沿后则需要更多：

- 提出没人问过的问题；
- 接受较长时间低确定性；
- 直接做原型；
- 让现实而不是身份判卷。

研究重点：

> **上一阶段最会赢的人，能否在下一阶段主动重新训练？**

## 7. 独立游戏为什么特别适合观察这种切换

独立游戏把很多大型组织内部被遮蔽的问题暴露出来：

- 谁真正出题；
- 谁亲自做 prototype；
- 错一个方向能活多久；
- 失败成本谁承担；
- 玩家反馈多久能回来；
- 项目是否围绕创作者真实能力设计；
- 大厂经验是可携带 capability，还是旧 objective function。

独立游戏不是天然更创新。

它只是经常提供一个更清楚的实验环境：

> **问题定义者、生产者和市场反馈之间距离更短。**

## 8. 创作者两轴模型

| | Problem Ownership 低 | Problem Ownership 高 |
|---|---|---|
| Production Maturity 低 | 菜鸟模仿者 | **前范式创作者** |
| Production Maturity 高 | **工业答案执行者** | **高成熟度作者型团队** |

本书真正关心的是：

> **一个前范式创作者怎样在获得 Production Capital 以后，不把自己的 Problem Ownership 一起交出去？**

## 9. 读者层要写的不是“老中批判”，而是创作者 Debugger

未来 reader-facing 结构优先使用：

1. 症状：你是不是正在等别人告诉你“正确赛道”？
2. 机制：你的学校/公司/行业过去奖励了什么？
3. 能力损失：它压低的是 problem ownership、prototype authority 还是 exit option？
4. 边界：什么时候 follow benchmark 完全合理？
5. 英雄反例：谁走了另一条路？
6. 压力反例：谁因为过度自信或反专家失败？
7. 行动问题：你现在能做的最小现实实验是什么？
8. 年份：这个方法在什么产业版本里成立？

所以“老中”在本书中的职责不是制造国民性解释。

它应该回答：

> **一个本来能力很高的人，可能在哪里被提前优化成了上一版本的优秀执行者？**
