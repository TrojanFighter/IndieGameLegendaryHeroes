# 声望管道与作者连续性 026：为什么同样进大公司，有人带走能力，有人带走评分器

- Status: RESEARCH NOTE / CROSS-LAYER SYNTHESIS / PRE-CLAIM
- Last verified: 2026-10-07
- Related: `AC-010`, `CASE-059`, `china-creator-constraints-three-layer-map-018.md`, `china-creator-three-layer-pressure-tests-019.md`, `china-creator-three-layer-failure-pressure-tests-020.md`
- Boundary: 比较“职业身份与作者身份如何耦合”，不把个案升级成中国/西方人格结论。

## 0. 研究问题

用户提出一个重要修正：

> 中国创作者的风险可能不只是“进大厂以后被旧 production regime 训练”。

更严重的可能是：

> **从名校绩优主义一路无缝进入名企绩效主义，导致外部评分器从学校延续到职业，直到想做独立游戏时才第一次真正失去标准答案。**

这个命题比“应试教育害创新”更可检验。

它预测的是：

```text
考试评分器
→ elite-school prestige
→ campus hiring
→ elite-employer prestige
→ performance/promotion
→ high salary/status
→ social legitimacy
→ independent transition requires multi-layer exit
```

如果耦合很强，独立项目就可能为了保全身份而操作变形。

# 一、Slay the Spire：Amazon 不是反例的全部，真正反例是“作者线程没有断”

CASE-059 已确认：

### Casey Yano
- 大学和 Anthony 一起做 Flash/mobile hobby games；
- CS 毕业后进入 QA/software 职业路线；
- Amazon QA 约四年；
- 自己说总体喜欢那里，但后来觉得无聊、想再做游戏；
- 先离开 Amazon。

### Anthony Giovannetti
- 同样有 college hobby-game prehistory；
- 长期 card-game / board-game taste；
- 管理过 board/card store；
- 做过 QA/software；
- 在工作期间继续写 Slay the Spire design document。

后来：

```text
old collaborator reconnects
→ design doc
→ Casey creates time
→ prototype
→ external playtests
→ Anthony quits
→ full build
→ metrics / Early Access / weekly patches
```

这里最重要的不是：

> “Amazon 没把 Casey 训练坏”。

而是：

> **Amazon 从来没有成为 Casey 唯一的身份来源。**

作者身份、朋友关系、失败小作品、游戏 taste 在公司之外有独立历史。

这叫：

> **Parallel Authorial Thread｜平行作者线程**

# 二、王妙一是中国的重要反例：问题不是“中国人必然被捕获”

王妙一 / WILL 已经证明：

- 清华高标准教育；
- 网易核心技术岗位；
- 大组织技术/流程训练；
- 仍然可以保留高度 Problem Ownership；
- 离职时主动重写 objective function；
- 并把“没钱、不会画，但会编程和写作”转化成 capability-shaped product。

所以不能写：

```text
中国名校
→ 中国大厂
→ 作者性消失
```

更准确是：

> **中国 prestige pipeline 可能提高 identity-capture 风险，但并不决定个体结果。**

王妙一和 Casey Yano 的共同点反而很接近：

- 大公司能力可迁移；
- 作者性有公司外来源；
- 离职不是否定职业训练；
- 新项目没有被旧公司规模/流程定义；
- 个人 taste 能直接定义产品。

# 三、月下是另一端：人离开公司，评分器还在

月下 / 《铸仙之境》提供了最强负压力之一。

已有公开复盘：

- 腾讯制作经验；
- 很快拿到大额融资；
- 团队一度 31 人；
- 多轮大改；
- 核心玩家流失；
- 后来自己总结最大的收获是“不要有乙方心态”；
- 早期感觉只是“换个地方上班”。

这个案例可以重新解释成：

> **Career Identity / Evaluation Function 没有随 Employment Exit 一起退出。**

即：

```text
company gone
但
external evaluator remains

老板
→ 投资人/发行
KPI
→ milestone / data demand
执行者身份
→ founder title without founder problem ownership
```

这就是：

> **Exit from Organization ≠ Exit from Evaluation Function**

AC-010 加的是：

> **有时这套评价函数甚至早于公司，在教育/名校/就业 prestige pipeline 里已经连续存在多年。**

# 四、Sea 是“主动卸载”的中间态

Sea /《安尼姆》不是完全负例。

更接近：

```text
big-company veteran
→ first independent attempt still carries old habits
→ expensive mismatch
→ explicit reflection
→ next project uses 1–2 person core demo before adding people
```

所以 deliberate unlearning 往往不是：

> “辞职当天完成”。

而是：

> **一次或多次项目失败后才真正发生。**

这对 reader layer 非常重要。

“大厂老兵转独立”应该问：

> 你有没有给自己设计一个**便宜到足以允许去大厂化失败**的过渡项目？

而不是第一作就承担：
- 大团队；
- VC；
- publisher milestones；
- 多年 burn；
- 家庭全部现金风险。

---

# 五、The Magic Circle：西方老兵也会遇到另一类失败

The Magic Circle 证明：

- BioShock / Thief / Dishonored 老兵；
- 真的拒绝 AAA process-heavy 文化；
- 三人核心；
- 强作者性；
- creator-project fit 很高；
- 最终商业仍不可持续。

因此：

> **成功卸载 prestige / process 也不是商业成功充分条件。**

它阻止我们把 Casey / 王妙一写成：

> “只要不被身份捕获，就会成功。”

真正模型必须保持：

```text
Authorial Continuity
+
Objective-function Reset
+
Cheap Validation
+
Market Sufficiency
+
Runway
```

# 六、真正值得跨国比较的不是“有没有绩优主义”

美国并不缺 pedigree hierarchy。

Rivera 的 elite-firm 研究显示：
- elite university prestige 是真实招聘过滤器；
- elite professional firms 集中在顶尖学校校招；
- prestige 与 cultural matching 都会进入录用；
- 这些工作拥有巨大收入与 status 回报。

中国研究同样显示：
- elite university 在 job entry 有显著 premium；
- institutional reputation 参与 graduate ranking；
- 高学历毕业生会形成 high-status occupational expectation。

所以两边都有 prestige。

真正要比较：

| 变量 | 需要问什么 |
|---|---|
| **Pipeline Coupling** | 学校 prestige 与公司 prestige 是否形成连续人生合法性？ |
| **Parallel Authorial Thread** | 雇佣之外是否持续有作品/社群/共同作者？ |
| **Side-project Legitimacy** | side project 是被视为正常技能/兴趣，还是“不务正业”？ |
| **Exit Optionality** | 离开后能否回来？resume gap 成本多大？ |
| **Household Expectation** | 家庭是否把 elite employer 当终局证明？ |
| **Employment Identity** | 公司是“我工作的地方”还是“我是谁”？ |
| **Prototype Status Cost** | 做一个丑小实验会不会被理解为职业降级？ |
| **Failure Legitimacy** | 一次不成功能否继续被视为高能力者？ |

这些才值得未来做中美/中欧比较。

# 七、Prestige-Preserving Project Distortion：独立游戏里的操作变形

如果 AC-010 成立，最危险的不是创作者不敢离职。

而是：

> **已经离职，但仍按 prestige preservation 设计项目。**

典型表现：

## 1. 先做 vertical slice，而不是 cheap truth

不是因为市场需要，而是：

> “必须让别人看出我们是专业团队。”

## 2. 先招完整岗位

因为：

> “正规游戏公司就应该有这些职位。”

## 3. 先复制成熟大作 representation

因为：

> “我以前做的就是这个规格。”

## 4. 不愿公开 ugly prototype

因为早期粗糙会伤害：
- 个人职业身份；
- 同行评价；
- 投资人印象；
- 家庭对创业的信心。

## 5. 项目必须解释得像一个“赛道”

如果不能说：
> “这是 X + Y，市场多大，竞品是谁”

就觉得它不够合法。

这些行为单看都可能合理。

只有当它们发生在：
> core product thesis 还没得到现实验证

才构成 Prestige-Preserving Distortion。

第一版只需要证明：

这就是 status cost 与 prototype cost 分离。

# 九、给“大厂老兵转独立”的新增审计

Creator Life / Decision Audit 增加三项：

### Identity Coupling
- 我的职业 title 是能力，还是自我价值证明？
- 如果下一作很小，我会觉得自己降级吗？

### Parallel Authorial Thread
- 过去三年有没有不受公司 KPI 支配的 artifact？
- 有没有非同事 collaborator / audience？
- 有没有自己长期积累的 taste / domain？

### Prestige-Preserving Distortion
- 项目哪些成本是真正产品需要？
- 哪些只是“看起来像专业项目”需要？
- 如果 nobody knew my résumé，我还会这样做吗？

这个最后的问题非常重要：

> **If nobody knew your résumé, would you still build the project this way?**

如果答案明显变化，prestige distortion 风险就高。

# 十、当前结论等级

### STRONG

- Casey Yano 的 Amazon 经历没有抹去大学时期作者线程；
- Slay the Spire 核心 thesis 来自长期 taste 与公司外 collaborator history；
- 公司能力可以选择性迁移而不复制公司 objective function；
- 王妙一提供中国同类反例；
- 月下提供“离职但评价函数没退出”的负压力；
- 美国 elite labor market 同样存在 pedigree prestige。

### HYPOTHESIS

- 中国名校→名企路径的 **pipeline coupling intensity** 是否高于美国科技/创意职业；
- 中国大厂老兵是否更常出现 Prestige-Preserving Project Distortion；
- side-project legitimacy、家庭 expectation、resume-gap penalty 是否是中美差异的重要中介；
- “好学生→大厂高绩效”是否让首次真正自主问题定义发生得更晚。

### REJECT

当前不允许：

- “西方人进大厂不会丢作者性”；
- “中国人一进腾讯网易就不会原创”；
- “Amazon 比腾讯/网易更自由”；
- “名校生不适合独立游戏”；
- “离开大厂就是找回作者性”。

# 十一、Authorial Initiation：第一次真正自主出题，发生在什么时候？（2026-10-09）

- **Status:** H / CROSS-CASE PRESSURE TEST / PRE-CLAIM。
- **Owner:** 本 026 负责“职业身份—作者身份—人生选择”；[018](china-creator-constraints-three-layer-map-018.md) 负责上游教育、PPAD、maker→career 与招聘筛选。DOOM 042/043 继续负责 early id 团队内的决策权/组织认知修枝；这里不建立重复版本。
- **Evidence boundary:** 公众资料中出现的企业/作品只按下列公开来源记录；私人聊天截图、非公开员工评价、私人项目内容不是本仓库的可发布事实源。聊天中的批评仅用于生成 H，不能反向转述为某个具体团队的已证问题。

## 11.1 三种不同能力：不能用 AAA title 一次证明

| 变量 | 在做什么 | 哪些证据比较可靠 | 不能推出什么 |
|---|---|---|---|
| **MAKING CAPABILITY / 制作能力** | 完成被给定的功能、资产、关卡或系统 | 具体 credits、负责范围、可运行 artifact、已完成任务 | 不能推出曾定义整个产品 |
| **PRODUCT-DEFINITION AUTHORITY / 产品定义权** | 确定目标玩家、核心幻想、产品问题、体验约束和取舍 | 公开主创决策记录、原型方向变更、production responsibility | 不能推出判断一定正确 |
| **AUTHORIAL JUDGMENT / 作者判断** | 在证据不完整时自己出题、取舍、调整、停止，并承担后果 | 连续原型—反馈—rescope/kill 决策链；本人说明 trade-off，同行/文档交叉验证 | 不能推出市场一定成功 |

**PRODUCT OWNERSHIP 不是版权所有权。** 本文说的是实际的 creative decision rights，不得从“创始人/制作人/总监”头衔自动推断 IP 法律归属、预算最终审批权或所有关卡细节的控制权。

因此新增：

### AUTHORIAL INITIATION / 作者性启动

> **一个人第一次自己提出可被现实检验的产品或体验问题，并对“为何如此、怎样做、何时修改/停止”承担有证据可追溯的实际决策责任。**

这是“人生中什么时候开始自己出题”的纵向事件，而非人格标签。不是只有独立创业才可能发生：学生社团、桌游、mod、公司内部获授权原创、个人原型都可以发生；协作作品需要区分本人发起权与跟随执行。

### AUTHORIAL INITIATION AGE / 首次自主出题年龄

只在有日期和出生信息时记录**可核年龄或区间**。没有直接证据则为 UNKNOWN；不能把“小时候爱玩”“是游戏专业”“某年成为 Creative Director”当作启动年龄。

建议人物审计逐条新增：
- **FIRST SELF-DEFINED PROBLEM**：首次主动定义的具体游戏/交互问题、年份/年龄及证据；
- **SELF-ORIGIN vs ASSIGNED**：自发提案、共创、课程/雇主给题，允许 MIXED/UNKNOWN；
- **EARLIEST AUTHORIAL ARTIFACT**：最早可查原型/作品，与真正的决策权分开；
- **DECISION RIGHTS MATRIX**：problem / core loop / scope / rescope / kill / budget / release，分别记 NO / SHARED / LEAD / UNKNOWN；
- **REALITY CONTACT**：第一次玩家/发行/销售反馈何时进入方案，如何修改判断；
- **PARALLEL THREAD**：进入名校/名企以后是否仍继续自己出题；
- **CONFIDENCE / CENSORING**：仅有晚年回忆时写 P1 和最早可观察下限；没有资料不是零。

**PPAD / 入职前作品密度**与**作者性启动**是两种变量：10 个照着 brief 生产的项目，可能证明很强制作能力，却没有足够证据证明独立出题；一个自己定义、迭代、砍掉的失败小作品，也可能证明真实作者判断练习。二者皆重要，且不能互相替代。

## 11.2 Warhorse：真正应比较的是独立创作前史与产品定义权，不是“欧美 AAA 工龄”

**Daniel Vávra 的本人回顾（P1）**：早年在 8-bit/Amiga 电脑文化中开始自己做东西，加入 Illusion Softworks 起初是美术人员，参与 Hidden & Dangerous 后在 Mafia: The City of Lost Heaven 担任 writer/designer/director，后来参与 Mafia II 的写作与设计。2014 年谈到创立 Warhorse 时，他明确把“现有公司无法做自己想做的游戏”列为创业动因，并说明自己在 Kingdom Come 继续担当 creative director、负责设计与写作。**这里不能把“参与 AAA”误写成他的首次作者实践；他此前已拥有重要的产品定义责任。**

- P1, Daniel Vávra interview (2014), Area Autodesk / RPGWatch 摘录：https://rpgwatch.com/news/kingdom-come--interview-area-autodesk-27879.html

**Martin Klíma 的本人回顾（P1）**：他在进入 Warhorse 之前很久已经通过 Altar 出版/设计桌面 RPG Dračí doupě 及后来的游戏项目，谈论游戏设计时强调从规则机制而非预设剧情出发；这说明 Warhorse 的联合创始人并非一批第一次拥有创作主权的高规格雇员。其桌游—出版—电子游戏的转换还包含商业发行、协调和团队冲突裁决经验，不应把他只当“另一位负责工程的人”。

- P1, Martin Klíma 访谈，Games.cz / Tiscali，2013：https://games.tiscali.cz/rozhovor/martin-klima-od-draciho-doupete-k-warhorse-225575
- P1, Warhorse 15 周年访谈，PC Gamer，2026-09-25：https://www.pcgamer.com/gaming-industry/game-development/for-warhorses-15th-birthday-we-chatted-with-its-co-founder-about-the-demand-for-grown-up-rpgs-ai-why-games-are-too-cheap-and-his-role-in-the-collapse-of-communism/

**市场与现实否决接口**：2014 年 Warhorse 的公开 Kickstarter 并不是“凭名声无条件拿到全额预算”。同期声明显示，此前约有 150 万美元投资；Kickstarter 达到目标被用来向既有投资人证明足够玩家兴趣，以便继续融资。这是“强作者性 + 现实验证 + 投资阶段性约束”，而非个人意志凌驾所有市场约束。

- P0, Crytek/Warhorse Kickstarter 新闻声明，2014-01-23：https://www.cryengine.com/news/view/kickstarter-for-kingdom-come-deliverance
- P0, 项目众筹页，2014-01-22—02-20：https://www.kickstarter.com/projects/1294225970/kingdom-come-deliverance

**允许的推论 H**：Warhorse 的路径更像“已获得作者性的人，将既有创作与职业生产能力重新组合”，而不是“AAA 雇员因资本到位突然获得作者性”。**禁止的跨国推论**：据此声称欧美/捷克 AAA 从业者普遍比中国 AAA 从业者拥有作者性；这是带强存活/媒体选择的个案。

## 11.3 Prestige-to-Authorship Transfer Error｜从履历光环误推作者能力

> **一个人在高规格商业制作中拥有高职级、优秀 credits、强工业执行能力，并不足以证明他已经独立承担过新产品的 problem framing、kill/rescope 与现实反馈判断。**

这不是否认高级员工技能，而是识别**测量对象错误**。建议创业/融资/媒体人物审计至少拆：
1. **Senior Specialist**：曾负责大型项目的一块子系统；
2. **Product-Definition Leader**：可核有重要方向定义与重大取舍责任；
3. **Independent Author / Founder**：带有自发问题、原型与可归因决策历史；
4. **Production Governor**：预算、团队、阶段性收敛/交付能力（可与前三者组合，非阶梯）。

### TiMi Montreal 的证据边界

Game File 2026-02-22 与 Game Developer 2026-02-23 报道：2021 年设立的 TiMi Montreal 约五年后关闭，未发行游戏，曾规划原创 AAA / service-driven 项目。该结果可以用于研究“组织耗时、项目未上市、进入市场反馈前就结束”的 production / capital allocation 问题。**但不能从“没有发售”反推具体创意总监没有过产品定义权、没有技术能力、或确定由中国母公司文化造成失败**；实际研发成本、内部 kill chain、公开试玩/市场测试、总部与工作室各方决策权均需独立证据。部分核心负责人在此前其他作品已有创意总监履历，更不应把整个案例粗暴当作“高级执行雇员没有创作主权”。

- S1, Stephen Totilo, Game File, 2026-02-22：https://www.gamefile.news/p/tencent-timi-montreal-closed
- S1, Chris Kerr, Game Developer, 2026-02-23：https://www.gamedeveloper.com/business/report-tencent-shutters-timi-montreal

因此必须分开：**prior decision rights / current organizational autonomy / scope control / market truth / shipped outcome**。仅靠一项结果不能识别另一项原因。

## 11.4 作者拥有主权，还需要生产治理：不要将“自由”当作充分条件

**AUTHORIAL SOVEREIGNTY ≠ PRODUCTION GOVERNANCE。** 自己能决定做什么，不等于能合理地控制团队规模、跨职能依赖、资产工作量、测试与上线义务；这与 [041 Ion Storm](truth-shield-to-narcissism-shield-ion-storm-governance-041.md) 的“高自主 + 低反馈完整性”风险一致。

聊天中的《动物派对》开发组织批评只能作为**未经核验的研究线索**，不得当作公司内部已经证实的岗位冗余或管理失当。可核的市场事实反而构成边界：作品于 2023-09-20 发售，首发服务器与联网设计争议曾见同期报道；到 2026-10 Steam 英文用户评论仍属 Very Positive，并持续更新。**生产流程争议、首发运营问题与商业失败是三种不同判断。**

- P0, Steam 产品和更新记录：https://store.steampowered.com/app/1260320/Party_Animals/
- S1, GamesRadar, 2023-09-20：https://www.gamesradar.com/co-op-hit-party-animals-already-has-over-100k-steam-players-but-mostly-negative-reviews-as-players-cite-server-problems-and-no-offline-mode/

这组样本不证明《动物派对》治理优秀，也不证明治理低效；要评人效，仍需 core/peak headcount、外包、实际预算、返工决策、上线和留存成本。

## 11.5 Evidence Accumulation vs Asset Accumulation｜烧资源以后到底知道了什么？

> **增加代码、模型、系统与制作团队，未必同步减少“核心玩家为什么需要这个作品”的不确定性。**

这可作为 H 级普适审计变量：**每次资源升级以后，新增了多少来自实际玩家的证据、哪些主要假说被确认/推翻、哪些资产因此被砍/重做？**

比较《逃离塔科夫》与《动物派对》时只能分析**反馈接口的时间结构**，不能从两款不同类型、不同平台/服务义务的作品直接排名 production efficiency。Battlestate 2016 年起已向限定用户开放 alpha、2017 年进入 beta，2025-11-15 才作 1.0 release；它的长期付费/玩家反馈循环是真实存在的。另一方面，长 EA 也可能拖延完工、服务于长期未解决的技术/运营债务，不能被神化。多人 party game 上线峰值的服务器压力则不能由少量试玩直接推断已验证。

- Battlestate release chronology / statements, 2025：https://outof.games/news/8328-escape-from-tarkov-to-finally-be-fully-released-on-november-15th-2025/
- Party Animals storefront/history 同上。

建议字段：
- **TIME TO FIRST EXTERNAL PLAYABLE TRUTH**：第一次有目标玩家真的玩到核心循环的时间；
- **VALIDATION DEPTH**：只是好评/播放量，还是有真实留存、付费、复玩、困难边界？
- **UPDATE-TO-SPEND**：阶段投入后解决了哪些关键不确定性？
- **ASSET LOCK-IN**：验证前形成了多少必须被未来方向继承的沉没资产？
- **CONDITION-SPECIFIC VALIDATION**：核心手感、多人承载、平台适配、内容供给等不可混为一个“已经测过”。

## 11.6 技术前沿扩张与产品搜索收缩：一个待检验的组织经济假说

### TECHNICAL FRONTIER EXPANSION × PRODUCT SEARCH CONTRACTION

随着实时渲染、美术规格、动画、技术管线提高，**技术上能够实现的体验集合**可能扩大；但如果资产成本、跨部门同步和返工负担增长得更快，企业在既定预算与收益要求下**愿意真正尝试的产品问题集合**反而可能收窄。

这是**条件机制假说**，不是“AAA 技术进步必然杀原创”。要同时测：
- 可用引擎/工具降低试作成本的部分；
- 生产规格提高导致的资产沉没成本；
- 验证前的预算/人员规模；
- 项目里实际存在多少非共识原型/被否方向；
- 取消/缩队与重新出题的成本。

可能的反例是成熟工具被重新用于便宜试验、强规模团队仍能推翻旧产品假说。技术前沿与“搜索成本”不是同义词，不能仅用画质或开发人数替代。

## 11.7 人物级前向假说与反证门槛

**H-A：** 在控制 pre-career maker experience、岗位、出生 cohort 和预算条件后，**更早拥有可证产品定义责任**的从业者，在后续独立 0→1 中可能更快建立可试玩核心和合理 scope。反证：大量早启动者仍持续无法验证产品；晚启动者凭公司内真实授权和强判断迅速学习。

**H-B：** 声望管道越连续，**Prestige-to-Authorship Transfer Error** 越可能出现在投资/招聘/媒体叙事；反证：同等履历背景下，实际授权与作品可验证程度解释力更强。需要跨国同岗 cohort，不能只拿失败的海外 AAA 创业者作分子。

**H-C：** **技术规格上升若未同步降低 prototype proof cost**，会提高前期 false-negative 与错误续命的风险；反证：工具降低成本、可验证性提高、迭代速度反而更快。

建议下次将本节字段并入既有 Creator Life / Decision Audit 的**可选扩展列**，不单独制造一张未抽样的人物评分排行榜。必须保留 UNKNOWN、反例、公众来源以及“能举出个例≠数量级相同≠强因果”的防错规则。
