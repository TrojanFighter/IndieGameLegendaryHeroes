# AC-003 — 世界模型、成本结构与生产能力

## 母题

作者与 ChatGPT 的长期讨论逐步形成了一个更抽象的问题：

> **开发者继承的“世界模型”本身，会不会像技术债一样，直接制造额外成本？**

这里的世界模型不是哲学修辞，而是从业者对“一个项目必须怎样被生产”的默认判断，例如：

- 什么事情必须由专门岗位完成；
- 什么规模才配叫商业项目；
- 哪些表现标准是不可放弃的；
- 哪些渠道、发行、融资方式被视为唯一道路；
- 什么叫“正规流程”；
- 哪些工作被默认只能通过增加人头解决。

## 生产单位想象

如果一个从业者只熟悉大型组织，其默认问题常常会变成：

> “我要凑齐哪些岗位，才能复制这个产品？”

而作者更关注另一种问法：

> **“我能不能改变问题本身，使它落入我的能力与资源边界？”**

这对应几个反复出现的判断：

- 不继承别人的成本结构；
- 不把大公司的组织图当成自然法则；
- 先识别不可改变的约束，再重构其余变量；
- representation、scope、技术路线与产品定义本身都是生产手段。

## 能力资本

这里的“能力资本 / capability stock”不是单项熟练度，而是一个开发者在长期职业与业余实践中积累的组合：

- 识别问题；
- 快速原型；
- 工程实现；
- 设计判断；
- 美术 / 音频 / 叙事等跨专业补位；
- scope ownership；
- 工具开发；
- 商业与市场判断；
- 对完成标准的作者性控制。

因此一个后来表现为 OPC / solo 的人，可能并非“一个人突然替代十个人”，而是已经把很多知识、判断和工具**内化或基础设施化**。

## 大组织经验的双重作用

作者历史讨论中形成的一个待验证判断是：

> 大型成熟商业组织既可能提供高质量能力资本，也可能通过极深专业分工，把人训练成只能在既有生产体系中高效工作的 A 型人才。

对作者性独立开发更重要的 B 型能力可能包括：

`问题发现 → 原型 → 产品方向 → scope → 跨专业补位 → 反复失败 → 市场接入 → 最终交付`

A 与 B 不是高低之分，而是能力结构不同。

## “工程障碍”与“问题重定义”同时成立

历史讨论中曾以 Paradox 式复杂策略游戏为例形成一个边界：

- 长期积累的 simulation architecture、脚本 / 数据系统、AI、存档、性能、UI、modding、QA 与 institutional memory 是真实壁垒；
- 但“无法直接复制成熟公司的全部生产系统”不等于“无法进入同一需求空间”；
- 新团队可以通过改变模拟粒度、表现方式、时间尺度、交互结构与内容生产方式重新定义问题。

因此本书不把“有工程壁垒”与“开发者拥有能动性”视为互斥判断。

## 可证伪形式

这一组观点至少需要回答：

1. 成功小团队是否真的经常改变 representation / scope，而非纯靠加班？
2. 大组织专业化是否可测地降低独立闭环概率，还是反而普遍提高它？
3. 开发者对项目成本的先验判断是否会显著影响其实际项目选择与完成率？
4. 所谓“能力资本”能否被拆成可观察前史，而不是事后给成功者贴标签？
5. 同样资源下，世界模型不同的开发者是否会选择系统性不同的生产路线？

## 禁止偷换

- “世界模型重要”不等于“物质条件不重要”。
- “可以重定义问题”不等于“任何问题都能被个人解决”。
- “大组织可能窄化能力”不等于“在大厂工作没有价值”。
- “小团队能做商业级产品”不等于“小团队天然更创新”。
