## 0. 本轮结果：找到了中国境内的“旁路创作”量表，但还不是游戏作者性调查

从国内中国游戏业的公开搜索继续追 `在职游戏开发者/私人游戏项目/问卷/创业意愿`，无法核验一份拥有**在职游戏雇员抽样框 + 个人游戏项目题目 + 每题答卷分母**的报告。可核的替代入口却呈现出一条研究机会：

1. 2024年开源社的**631名自愿参加者**问卷测到自主技术社区参与、贡献、每周时长、激励因素与校园/职业背景；**不是游戏雇员总体**。
2. 2024年CSDN的IT开发者公开调查提供了职业、技术与开源领域的应答者态度；其招募渠道是CSDN/《新程序员》自愿参与，仍不具备游戏从业者人群总体分母。
3. 2023年已有一个《中国独立游戏从业者生存现状调查》的公开**问卷招募帖**，但目前没有核对到结果数据、样本规模或完整题目。证明有过招募行动，不证明调查已经完成。
4. 2025年《澎湃新闻》对中国独立游戏线上社群做参与式观察并采访**6位独立开发者**，直接描述现金/伙伴/发行障碍；有传记/机制价值，不能推出人数分布。
5. 有原文可核的**软件职务作品/职务软件权属及竞业限制条款**。法律上的合理界限和雇员主观担忧之间存在待测的空间；不可以“法律允许/禁止”替代实际职场和心理数据。

研究策略由单纯 `CN vs Europe rates` 改为**同一中国受访者内部的跨活动配对**：业余代码/开源贡献、个人游戏原型、工作岗位的设计决策权分别观察。它能回答更细的“技能可迁移，却为何不转化成自主游戏项目？”；不能单靠截面调查给出因果结论。

## 1. 开源社《2024中国开源年度报告》的真正统计对象

**P0：开源社原始报告（GitHub public repo, questionnaire.md）：**
https://github.com/kaiyuanshe/2024-China-Open-Source-Report/blob/main/questionnaire.md

**调查机制：** 问卷于公众号、开源社、OSCAR产业大会、PyCon、中国开源年会等线上线下渠道征集；**631份问卷、41个问题**。对象覆盖开发者、社区参与者、学生及管理者等，绝非所有中国程序员的随机样本，更非游戏企业员工名册。

**结果/限制：**

| Original item / description | Report's respondent-based figure | Correct reading |
|---|---:|---|
| 在校学生 | **36.3%** | 约三分之一为学生，不能作为纯「受雇员工」统计 |
| 互联网/IT/电子/通信行业 | **72.23%** | 跨行业科技人群，未区分游戏雇员工作年限 |
| 自报开源「使用者」 | **72.1%** | `OPEN_SOURCE_USER` ≠ `AUTHOR` |
| 自报「参与者」 | **55.1%** | 互动、参加社群可能无作品；与使用者/贡献者分类可以重叠 |
| 自报「贡献者」 | **29.5%** | 在自愿受访人群内真实有开源贡献的描述；非「29.5%中国人会自主游戏设计」 |
| “超过半数的贡献者每周>5小时，超过20%每周>10小时” | subgroup-only | **贡献者条件样本**，不是全体631人的分布；问项原分母未显示，保留 `N_item_UNKNOWN` |

报告自述代码、文档及运营均属于贡献活动；代码贡献本身也不必然是**自主立项原创产品**。如果一个受访者只是给公司技术栈工具修bug，和自己设计游戏机制是两种作者性。

**报告内部质量检查**：问卷「结果预览」概述称男性女性约各半，但后续 §3.1.1 又给出**男性71.0%、女性28.4%、其他0.6%**。两处明显不一致。该缺口不能被悄悄修补；在缺少更完整原始表和明确有效答卷口径时，**不使用“性别代表性好”等论断，不把本问卷作为推断中国普通技术人群的概率样本**。报告还使用“具有良好的地理代表性”等措辞，但其自身说明线下活动渠道集中于北京/广东/上海，不能从城市覆盖广推统计代表性。

**H级竞争解释**：有可行的代码开源社区，不等于存在同等容易的 game-author discovery、资金与发行系统。我们应测「此人业余贡献开源」和「此人独立制作游戏」是否同行并存，尤其比较同岗/同收入/同城市的差异。不可用上述29.5%跟欧洲《Big Games Industry Employment Survey》41% pet project 并列当民族差距。

Sources:

公开稿讨论IT开发者工作岗位/晋升意愿/薪酬/工作时长/开源/AI，报告中「跳槽原因」等百分比只有在答题者的适用子集下才有意义。由于本轮没有读到可核准的**游戏行业子样本数量、是否问私人游戏项目、每题有效样本量、加权与非应答处理**，只能记录 `RELEVANT_GENERAL_DEVELOPER_SURVEY / NOT GAME EMPLOYEE DATA`。不要把“某些参与开源的开发者利用业余时间”直接翻译为“35%在职中国游戏人做独立游戏”。

## 4. 中国国内2025年近场机制材料：资金、合作与市场接入

**S1 带部分P1受访者原话**：澎湃研究所 欧阳启翾/戴媛媛，2025-01-17《当“做游戏”成为一场生存游戏：独立游戏开发者的挑战关卡》，https://www.thepaper.cn/newsDetail_forward_29955483 。

方法：2024-11至2025-01在独立游戏线上社群做参与式观察，**6名开发者**接受采访。适合提炼本人经历和组织机制，**不是劳动市场计量研究**。

作者/受访者触及三种机制：
- **TIME / CASH RUNWAY**：自主小团队开发期间收入不稳定，有的人通过外包、众筹、投资与严格限定成本维持时间。
- **TEAM CONTRACT / CONTINUITY**：无薪或柔性组队降低进入门槛，却在劳动质量、决策分歧和成员退出上产生不同于雇佣制的风险。
- **DISCOVERY / DISTRIBUTION**：游戏完成后还需要被市场发现；玩家反馈、平台发布、宣发转换、国内出版审批与交易成本等问题应分别核。
- 研究者还转述indienova平台内“登记开发团队约半数为单人”的站内数据。**没有公开可核的站内总数/采样时间与定义，因此不可升级为中国全部独立开发团队单人率**。

**文章两处定义型推断需要锁定：**
1. 文章开头把独立游戏定义成**不依赖任何商业投资**，后文却又列举投资作为生存手段。这不是可强制所有研究者采用的行业定义。必须区分 `INDEPENDENT_AUTHORSHIP`、`NO_EQUITY`、`NO_PUBLISHER`、`SELF_FUNDING`：拿投资不自动失去作者决策权，自筹资金也不自动拥有艺术自主权。
2. 文章转述版号常见周期与总成本等数字，没有逐项原始办理账单/所有平台适用范围。若以后用于出版/法律或具体工作建议，**须另行核验2026政策、真实个案和官方规则**；本研究只登记「开发者报告制度摩擦」，不把一个媒体估值默认为所有作品的真实门槛。

因此，这6位受访者确实能让研究解释「完成作品/持续制作的现实成本」，但没有一个有资格回答「在职游戏人中有多少已失去作者性」。

## 5. 容易被忽略的中国制度变量：`IP_PERMISSION_CLARITY` 不等于 `ALL_SIDE_GAMES_BANNED`

### 5.1 职务软件著作权：法律确实设置边界，而非“雇主自动拥有你做的一切”

**P0 国务院《计算机软件保护条例》现行可核的2013修订文本**，司法部国家行政法规库：
https://xzfg.moj.gov.cn/front/law/detail?LawID=581

其第十三条列出的职务软件归单位的特定条件：
- 本职工作明确指定的开发目标；
- 作为本职工作可预见或自然的结果；
- 主要使用组织资金、专用设备、未公开专门信息等条件、并由组织承担责任。

第九条先规定通常归开发者，第十条对合作开发的权属要求书面合同；职务软件第十三条规定了例外。**不能由“下班后开发”就断言属于员工本人，也不能由“在游戏公司任职”就断言所有私人程序归雇主**。具体还可能涉及劳动合同、保密义务、其他资产著作权、雇主机密和权利链；这里不作个人法律意见。

### 5.2 竞业限制：2025年9月起的司法解释提供实质界线，但非免费私人游戏许可

**P0 最高人民法院《审理劳动争议案件适用法律问题的解释（二）》**，2025-08-01公布，2025-09-01施行：
https://www.court.gov.cn/fabu/xiangqing/472691.html

- 第13条：若劳动者未接触、未知悉相关商业秘密和与IP有关的保密事项，其要求确认竞业限制条款不生效，法院应支持；范围、地域、期限不相适应的超过合理范围部分也可认定无效。
- 第14条：对于符合限定身份与保密条件的人员，不能仅以“在职不得约定竞业限制”或“在职没有支付经济补偿”为由否定在职竞业约定。
- 第15条：对违反有效约定的责任保留支持。

**明确分开**：`POST_EMPLOYMENT_NONCOMPETE`、`IN_EMPLOYMENT_COMPETITION`、`TRADE_SECRET`、`EMPLOYMENT_IP`、`COMPANY_SIDE_PROJECT_POLICY`、`PERCEIVED_RISK` 是六个不同变量。该司法解释不是允许所有中国游戏开发员工无条件在职推出竞品的许可证；法律对竞业限制的界定也不等于雇主实际是否鼓励独立作品。

2025司法解释比2013软件权属制度要新；做时代比较必须按事件当时的法令有效期，不允许用2025法解释直接取代2019年某个雇佣合同的历史情景。

### 5.3 有证据的“压制作者性”需要识别四层，不能根据法律直接推发生率

1. `DE_JURE_RIGHTS`：法律明确了什么、在何时有效。
2. `CONTRACTUAL_TEXT / COMPANY_POLICY`：实际合同/员工手册里写了什么（若无合法公开或经许可的信息，保持 UNKNOWN）。
3. `EMPLOYEE_BELIEF`：开发者**认为**自己是否被许可做个人项目；即使认知有误，它也可能影响行动。
4. `PRACTICED_AND_ENFORCED`：实际项目是否申报、是否获批、是否发生过权利争议；必须有可核、合法、非识别的聚合/司法数据。

这也是 2025司法解释的一个可能研究窗口：在条文生效前后，人的实际了解、制度改变和业余项目行为是否变化？`LAW_IN_BOOKS` 不能自动推政策改变引发了创作率变化；法律更改和整体市场变化同时发生，需明确比较组及模型。

## 6. 下一阶段真正可行的最小比较：**在同一中国雇员内部配对技术性创作与游戏作者性**

过去的国别比较容易把“欧洲程序员回答pet project”的41%和“中国游戏公司没有Steam产品”拿来对比；这完全不合格。较好的下一个问题是：

> 给同一个人，同一个12个月窗口：他是否有**自主选择问题、非雇主指派**的程序/开源/工具项目？是否有自己发起的**游戏玩法或艺术表达**项目？若二者不同，时间、技能与产权信念谁是主要阻碍？

建议经合规渠道对 **有公开名单/确定群体分母、取得组织许可的中国游戏技术岗位 cohort** 匿名抽样，同时纳入策划、美术，另用非游戏IT岗位做内部负控制，**所有人回答同一问卷，哪怕没有任何私人项目**：

| Matched dimension (same respondent, last 12 months) | Exact survey target | Common invalid proxy |
|---|---|---|
| EMPLOYED_STATUS | 公司、岗位类别、从业年限，避免直接收集真实公司名称 | 游戏社群身份≠正式员工 |
| SELF_DIRECTED_TECH | 私人程序、开源贡献、个人工具、非工作指派的原创模块（是否可选择目标/改方向） | 在开源软件上提issue≠自主项目 |
| SELF_DIRECTED_GAME | 纸面设计、Mod、自研玩法、私下可玩原型、团队合作、公开/未公开游戏 | 没有Steam页面≠没做 |
| DESIGN_RIGHTS_AT_WORK | 在公司对题材、玩法、范围、原型验证的主导/否决/裁切权 | 职级高≠设计主导 |
| DESIRE | 想不想继续做自己的游戏（NO/YES/UNSURE/REFUSED） | 想创业≠有原型 |
| RESOURCE | 工时、通勤、照护、每周自由时段、储蓄缓冲区间、团队人才缺口 | 工资高≠可无风险创业 |
| RIGHTS | 自己是否知道工作外创作规则、是否相信可公开/商业化，有无实际**明示允许/禁止/不确定** | 法律文本≠实际感受/合同内容 |
| MARKET | 曾否独立测试、申请发行、上架/退款/发行商联系 | 玩家数量与个人创作能力不是同一变量 |

重点是人内的 `TECH_YES/GAME_NO`、`TECH_YES/GAME_YES`、`TECH_NO/GAME_YES`、`BOTH_NO` 四格，再在每格比较职业/时间/兴趣/法律认知。**不是把技术开源“更高尚”或不做游戏解释为缺乏创意**：技术与设计有不同兴趣和回报；对全职策划/美术必须采用对应非代码自主艺术/叙事问题测量，防止技术岗天然占优。

如没有合格机构人群样本，则只能做 `VOLUNTARY_MECHANISM_INTERVIEWS`，公开人数与来源，不宣称占比。重复回访至少3个时点方能谈「入大厂前后作者性如何变化」；横截面分组可能有岗位自选择、职业发展和 survivor bias，绝不能轻率给因果。

## 7. Source/quality ledger and conclusions allowed

| Evidence | Quality | Supports | Does NOT support |
|---|---|---|---|
| 开源社 2024 原始问卷报告（631） | P0 organizer / nonprobability | 在技术圈有可测的自主贡献形式、在线抽样结构和报告内部文字冲突 | 中国雇员/游戏人私人原型比例 |
| CSDN 2024 自愿开发者报告 | P0 organizer / nonprobability | 技术岗/薪酬/开源等问卷机制的存在 | 具体游戏雇员作者性与中国/欧洲对比 |
| 机核2023调查招募帖 | P0 recruitment only | 游戏圈曾征集独游生存问卷 | 任何已发生的结果或比例 |
| 澎湃2025六人深访 | S1 narrative + interview P1 excerpts | runway、稳定组队、发行障碍作为真实案例候选 | 国内独立游戏开发者普遍薪资/项目退出率 |
| 司法部2013现行软件保护条例 | P0 legal text | 职务软件和合作软件的权利条件 | 企业条款分布或任何人主观创作恐惧率 |
