# CASE-003 — Papers, Please / Lucas Pope

- Status: RESEARCHING
- Subject: Papers, Please / Lucas Pope
- Related Claims: C003, C004, C006, C007, C009, C010, C011

## Why this case

检验一个成熟 AAA 开发者转为个人作者型生产时，真正迁移出来的是什么：不是大团队预算，而是**完成项目、做工具、判断删减和公开验证**的能力。

## Myth

> Naughty Dog 程序员离职后，九个月独自做出一款小品神作。

第一轮证据表明，“九个月”是真实项目期，但不是能力起点：Pope 此前已有长期个人制作、Ratloop、serious games 与《Uncharted》系列经验；而且项目最初只计划六个月，公开 beta / Greenlight / 媒体反馈改变了投入决策。

## Origin / Capability

当前可支持：
- 早年使用 HyperCard / C64 等制作；
- 大学后与伙伴成立 Ratloop；
- 在 Realtime Associates 做 serious games；
- 在 Naughty Dog 参与前两部 Uncharted；
- 一直希望回到更小、更实验性的个人项目。

Pope 自己明确把 AAA 经验中“nothing is above being cut”视为完成游戏的重要能力。

## Timeline — first pass

- 2012 年末：开始 Papers, Please 开发并公开 devlog。
- 2013-03：公开 beta 已包含前 8 天。
- 2013-04：准备 Greenlight / trailer；原计划约再做一个月左右。
- 前四个月：公开开发、收集反馈、做到接近 public beta。
- Greenlight / 媒体关注后：把原计划 6 个月延长约 3 个月用于打磨。
- 2013 夏：补全故事、经济和后续日程；大量机制被删。
- 总开发期：约 9 个月。

## Scope / Cutting as Capability

Pope 的开发日志给出异常清晰的一手证据：
- 行李检查、威胁/枪械、UV seal 等系统被取消；
- 判断标准不是“做不出来”，而是 payoff 是否值得 implementation cost；
- 他把删减视为集中核心体验的主动设计工作。

因此本案对 C007 的更精确表述是：
> 小团队优势不只是做“小东西”，而是更强地把功能成本与体验收益直接绑定。

## Market as Production

“零营销”不成立：
- 公开 TIGSource/devlog；
- beta；
- trailer；
- Steam Greenlight；
- 媒体报道；
- 后续本地化甚至公开工具并组织约 100 人测试。

Greenlight/媒体热度还反向改变了项目生产周期：Pope 明确说因此多投入三个月 polish。

## Runway / Family Constraint

后续回顾显示，项目开始时妻子正怀孕；家庭计划对 downside 有真实约束，Pope 当时的思路是先做完这个项目，之后必要时重新找工作。

但当前缺：
- 储蓄规模；
- 住房/家庭收入；
- 具体机会成本。

## Preliminary Verdict

> Papers, Please 的异常不在于“九个月速成”，而在于 Pope 把多年专业与个人开发经验压缩进一个非常小的生产函数：自制工具、公开 beta、Greenlight 验证、严格删减和对再次就业的可逆性，共同让一次作者型实验具有可控 downside。

## Open Questions

1. 离开 Naughty Dog 到 Papers, Please 的资金 runway？
2. 妻子收入/家庭支持在项目期的实际作用？
3. Greenlight / beta / 媒体各自对销量与开发延长的因果权重？

5. AAA 经验中还有哪些能力直接迁移，哪些反而被主动抛弃？

## Creator Life / Decision Audit

- **Audit status:** SUBSTANTIAL
- **Life stage:** 成熟职业开发者转个人作者型生产；项目开始时妻子怀孕，家庭 downside 真实存在。
- **Household:** married/partnered；pregnancy 已有公开回顾支持；住房、配偶收入、家庭资产与后续 childcare 结构 `UNKNOWN`。
- **Runway:** 离开 Naughty Dog 后依赖既有职业积累与个人 runway；精确储蓄未知。项目原计划约 6 个月，Greenlight / 媒体反馈后再增加约 3 个月 polish。
- **Household burn:** `UNKNOWN`；但“做完这一作，必要时重新找工作”说明家庭现金约束与职业可逆性同时进入决策。
- **Exit / recovery:** **HIGH EXIT OPTIONALITY** — 有 Ratloop、serious games、Naughty Dog / Uncharted 职业前史，且本人明确把重新就业视为现实后备路径。
- **Capability vector:** programming / tools / game production / scope cutting / design judgment 强；个人项目经验与 AAA shipping experience 同时存在。
- **Problem ownership:** **HIGH** — thesis、工具、scope、删改与发售节奏由 Pope 直接掌握。
- **Validation architecture:** devlog → public beta → Greenlight / media signal → additional polish → launch。
- **Reality adjudication:** **STRONG** — beta /公开反馈改变了投入时长；大量已实现或计划机制因 payoff 不足被删除。
- **Capability capture risk:** **LOW** — 当前证据显示技术与工具能力服务于快速删减和产品 closure，而非形成独立技术前沿。
- **Market sufficiency / legibility:** **STRONG** — “边境检查员”高概念、beta 与 Greenlight 在正式发售前已提供明确市场可读性。
- **Capability scaling:** core solo-author production + localization / testing / platform perimeter；完整 contributor boundary 仍需继续核。
- **Major unknowns:** 离职时储蓄规模、配偶收入、家庭月 burn、住房、Greenlight /媒体信号各自的真实因果权重。
