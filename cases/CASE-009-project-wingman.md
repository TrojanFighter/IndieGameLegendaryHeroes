# CASE-009 — Project Wingman / Sector D2

- Status: RESEARCHING
- Subject: Project Wingman / Sector D2
- Related Claims: C003, C004, C006, C007, C008, C010, C011, C012

## Why this case

游戏炼乳把 Project Wingman 当作“技术饱和时代，小团队可以用通用技术挑战成熟大厂品类”的代表。本案要核验这究竟来自工具平权、个人能力、社群协作、众筹，还是隐藏的外部生产网络。

## Myth

> 一个没做过游戏的人 / 三人小组用 Unreal 做出独立版《皇牌空战》。

第一轮资料给出更精确的版本：
- Abi Rahmani 确实说此前没有完整游戏，只做过一个很小的 UE4 prototype；
- Project Wingman 本身就是从这个学习 Unreal / 3D 实现的小 prototype 演变；
- 2017 年他已持续开发约两年，并公开多个 alpha；
- 他明确否认这是“full one-man effort”：社区志愿者帮助小项与快速反馈，Jose Pavli 负责音乐；
- 2018 年采访又确认故事/配音协调等由 Matt 等人协助；
- Kickstarter 后又获得更大的生产 runway，后续 console 还存在平台/发行协作。

## Capability / Learning

Abi 的直接访谈很适合检验“能力是项目过程中生产出来的”：
- coding；
- 3D modelling；
- animation；
- texturing；
- marketing / publishing；
- 依赖互联网学习资料和 UE4 社区。

因此 CASE-009 与 FTL/Gunpoint 不同：
> 开工前能力资本较少，但通用引擎 + 网络学习 + 公开 Alpha + 社群反馈把项目本身变成长期训练场。

## Runway / Market

已核 Kickstarter：
- goal AU$35,000；
- pledged AU$114,544；
- 2,467 backers；
- 2018-05-29 至 2018-07-03。

但 Kickstarter 不是起点：
- 项目在 2015 左右已开始；
- 公开 Alpha 和本地展会反馈先于众筹；
- Kickstarter 更像中期验证 + runway 放大。

## Production

必须拒绝“3 人 = 没有外部贡献者”的简写。

已知至少：
- Abi Rahmani：核心开发、3D、美术/技术等；
- Jose Pavli：音乐；
- Matt / Matthew Nguyen：故事相关与 voice actor coordination（需继续核 credits）；
- 社区成员的志愿帮助；
- 后期平台/发行支持。

## Preliminary Verdict

> Project Wingman 的真正异常之处不是“三个人复制 AAA”，而是把成熟商业引擎、互联网学习、公开可玩版本、细分品类知识、社区免费/低成本反馈、众筹资金和少量专业协作者组合成一个足以攻击旧高成本品类的问题结构。

## Creator Life / Decision Audit

- **Audit status:** PARTIAL
- **Life stage:** Abi Rahmani 从极少正式游戏开发经验的个人学习者进入长期项目；项目本身承担能力形成。
- **Household:** relationship / children / housing / family support `UNKNOWN`。
- **Runway:** Kickstarter 前生活来源和每周工作状态仍 `UNKNOWN`；2018 Kickstarter AU$114,544 / 2,467 backers 属中期 runway 放大，而非起点。
- **Household burn:** `UNKNOWN`
- **Exit / recovery:** `UNKNOWN` — 没有足够职业前史材料。
- **Capability vector:** coding / 3D modelling / animation / texturing / marketing-publishing 在项目中逐步形成；社区志愿帮助、音乐、故事/配音等外围补缺。
- **Problem ownership:** **HIGH** — prototype 起于个人学习/兴趣，不是外部 brief；核心 flight-combat thesis 长期由 Rahmani 驱动。
- **Validation architecture:** tiny UE4 prototype → public alpha / local events → community feedback → Kickstarter → expanded production → commercial release / platform support。
- **Reality adjudication:** **STRONG LEARNING-SIDE** — 项目通过公开 alpha 和社区不断校准；但哪些大设计因 feedback 被删除仍需更细。
- **Capability capture risk:** **MEDIUM / LEARNING COUPLED** — 自学大量工种可能造成 founder throughput risk，但 current evidence 仍显示产品持续对外可玩，而非纯技术自嗨。
- **Market sufficiency / legibility:** **STRONG NICHE LEGIBILITY** — “indie Ace Combat-like” 对既有飞行战斗受众高度可读；Kickstarter 前已有公开 traction。
- **Capability scaling:** **PROJECT-AS-EDUCATION → CROWDFUNDING / COMMUNITY PERIPHERY** — 能力不是预先齐备，而是在项目中生产出来。
- **Major unknowns:** Kickstarter 前收入来源、Sector D2 成形时间、全部 credits、Humble/Microsoft 支持、household conditions。

## 技术机会窗口与验证阶梯（2026-10-09）

- **技术条件（初步归档）：** 2015–20｜Unreal等通用3D引擎。
- **实际体验验证与进入市场的路径：** 公开试玩→社区/众筹→大规模飞行游戏。
