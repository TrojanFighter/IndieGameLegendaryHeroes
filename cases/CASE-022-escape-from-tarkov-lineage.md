# CASE-022 — Escape from Tarkov / Contract Wars → Battlestate Games

- Case ID: CASE-022
- Subject: Escape from Tarkov / Contract Wars → Battlestate Games
- Related games: Contract Wars; Hired Ops (parallel comparator); Escape from Tarkov
- Period covered: c. 2010–2025
- Research status: RESEARCHING
- Last verified: 2026-10-04
- Related Claims: C002, C004, C006, C008, C010, C011

## Why this case

这不是单纯研究“塔科夫如何发明 extraction shooter”。本案检验一个更基础的生产问题：

> **一个团队能否先用更低风险、更商业化、更受平台约束的项目生产技术、团队经验与现金流，再把这些积累兑换成一款按行业常规看过于昂贵、过于硬核、过于难卖的原创项目？**

现有证据已经足够把 `Contract Wars → Escape from Tarkov` 从作者旧有推测升级为有直接来源支持的生产谱系；但 `Hired Ops` 必须从“前作链”里拆出来，作为 AbsolutSoft 在组织分流后的平行分支处理。

## 1. Myth

流行叙事容易把 Escape from Tarkov 写成两种相反神话：

1. **凭空豪赌神话**：一群俄罗斯硬核枪迷不顾市场，突然押上一切做出前所未有的超硬核 FPS；
2. **低成本俄罗斯奇迹神话**：因为当地人工便宜，所以小公司可以用很少的钱做出西方 AAA 做不到的复杂游戏。

两种说法都漏掉了同一件事：Battlestate 的奠基团队不是从零开始。他们在 AbsolutSoft 的 `Contract Wars` 上已经完成了一轮商业化 FPS、Unity 技术、在线运营和资金积累。

## 2. Origin

### Contract Wars / AbsolutSoft

- `Contract Wars` 是基于 Unity Web Player 的浏览器 FPS；
- Battlestate 后来的奠基团队在 AbsolutSoft 制作这款游戏；
- Nikita Buyanov 后来直接把它描述为：用于“试技术、理解我们能做到什么，并赚到继续工作的资金”的项目；
- Unity 官方案例也明确说，Contract Wars 的开发让团队获得新技能、FPS/Unity 专业知识，并积累了创办 Battlestate 所需资金。

### Battlestate 的成立

因此更准确的起点不是“EFT 项目创建日”，而是：

`AbsolutSoft / Contract Wars → 人才与能力积累 → 资金积累 → 部分核心成员形成 Battlestate → Russia 2028 / EFT`

这是一条**能力与资本从较低承诺项目向高承诺项目升级**的路径。

### Hired Ops 的位置

Hired Ops 由 AbsolutSoft 继续开发，并明确继承 Contract Wars 的部分系统与玩家关系。它与 EFT 共享明显的题材/世界观血缘，但当前证据不允许把它写成 Battlestate 的直接前作。

更合理的结构是：

```text
                    → AbsolutSoft → Hired Ops
Contract Wars ──────┤
                    → 部分原团队 / 能力 / 资金 → Battlestate → Escape from Tarkov
```

这正好提供了一个珍贵的内部比较：**同一能力母体如何分叉出更传统的 session/F2P 延续路线与更激进的 hardcore premium 路线。**

## 3. Capability

Contract Wars 至少为后来 EFT 生产了四类能力资本：

- **FPS 设计能力**：枪械手感、战斗节奏、现代 PMC 题材；
- **Unity 工程能力**：Unity 官方直接称团队由此获得对 Unity 及其系统的深度理解；
- **在线产品能力**：多人服务、更新、玩家行为与长期运营；
- **团队共同经验**：不是临时拼装一批第一次合作的人，而是从旧项目中带出共同语言与已验证协作。

因此 EFT 的“高复杂度”并不是在一个真空中一次性承担，而是建立在**已经被较小产品支付过学费的技术栈**上。

## 4. Runway

| 阶段 | 来源 | 金额/口径 | 证据 | 置信度 |
|---|---|---|---|---|
| Contract Wars | F2P 浏览器产品收入 | 未找到可审计总额 | E001, E002 | 高（存在收入并用于下一阶段）；低（具体金额） |
| Battlestate 创建 / EFT 前期 | Contract Wars 累积资金 + 团队自有投入 | Buyanov 称无投资人；精确 burn 未知 | E001, E002 | 中高 |
| EFT 2016 Alpha 起 | 官网预购，多档 package | contemporaneous pricing / alpha-access 证据存在 | E004, E005 | 高 |
| EFT 长期 beta | 直接销售 / 预购式持续现金流 | 具体年度收入待补 | E004, E007 | 中 |

本案最重要的资金结论不是“Contract Wars 赚了多少钱”，而是两条更保守、但已经有直接证据支持的判断：

1. **它确实产生了用于下一阶段的资金；**
2. **它同时产生了下一阶段会用到的技术与团队能力。**

因此它不是单纯的“赚钱前作”，而是一个多维 staging project。

## 5. Production

Escape from Tarkov 后来发展为远大于典型独立团队的在线项目。Unity 案例采访时已经描述 Battlestate 为约 80 人开发团队。

但“大团队”是后来的结果，不应该反过来覆盖其生产起点：

- 核心能力在 Contract Wars 阶段已经形成；
- 团队先有可商业运行的较低风险产品，再建立专门承载 Russia 2028 / EFT 的组织；
- 之后随着 EFT 的内容、网络、资产与 live-service 需求增长，组织规模才同步扩大。

这一点与 Minecraft / Among Us 等“小团队成功后再组织化”案例不同：EFT 是**先用前作制造组织能力，再用新公司承载一个从一开始就高度超范围的项目**。

## 6. Scope

### 从 F2P session shooter 到 premium hazardous-environment simulator

真正激进的不是“把 Contract Wars 做大”，而是主动拒绝最容易继承的答案。

2016 年 Buyanov 对 GameSpot 明确表示：EFT 将是传统完整购买，不做 F2P / microtransaction；同时他把设计目标描述为现实、困难、并不追求传统 FPS 意义上的轻松 fun。

这意味着团队把 Contract Wars 已验证的：

- Unity 技术；
- FPS/枪械能力；
- PMC / Russia 2028 题材；
- 在线服务经验；

保留下来，却没有简单复制其：

- 浏览器平台；
- F2P 商业模型；
- 短局 session shooter 产品定义。

**能力复用与产品否定同时发生。** 这是本案最值得保留的生产史特征。

## 7. Failure / Risk

- Contract Wars 本身不是失败前作，而是较低风险的训练与融资产品；
- EFT 最早的公开计划显著低估了项目时间，2016 年时团队仍预期很快完成正式版本；
- Buyanov 在 2025 年 1.0 前回顾时承认，他们原本计划更早完成，过程中遇到大量子系统障碍，部分内容需要从零重写；
- 因此 EFT 的长期 beta 不能被事后浪漫化为“十年计划”：它也包含严重的估期误差、技术返工与 scope 扩张。

## 8. Market

Escape from Tarkov 的市场接入同样不是“产品自己火起来”。其关键路径包括：

- 2015 年末公开曝光；
- 2016 年起通过官网销售多档预购 package；
- 高价版本与 Alpha access 绑定，为早期开发提供现金流；
- 2016 Alpha 已向预购用户逐批开放；
- 团队最初计划先走自己的 launcher / platform，再考虑 Steam；
- 长期测试社区、视频/直播传播和硬核口碑逐渐构成市场基础设施；
- 直到 2025 年 1.0 才正式进入 Steam。

因此 EFT 是一个很强的 C010 案例：**分发、预售、测试资格、社区曝光本身就是融资与生产系统的一部分。**

## 9. Environment

### 有利因素

- Unity 使 Contract Wars → EFT 的技术能力具有较强连续性；
- 浏览器 F2P 先提供了较低门槛的商业试验场；
- 数字直销允许团队绕过传统 publisher，在官网卖预购并持续融资；
- PC 硬核社区允许一个极端产品在未进入大众零售/Steam前长期积累受众。

### 约束

- 自建 launcher、账户、服务器、反作弊、支付与全球运营把传统发行商/平台承担的职责重新压回团队；
- 长期 live development 带来持续技术债与基础设施压力；
- “没有外部投资人”换来的是更强创作控制，同时也意味着更集中地承担产品风险。

## 10. Luck

现有证据能证明团队**刻意制造了一个有能力、有 runway、有明确定位的高风险赌注**，但不能证明后来 extraction shooter 的品类级爆发可以被事前预测。

需要区分：

- 可控：Contract Wars 训练、资金积累、硬核定位、商业模型、直销和持续开发；
- 部分可控：口碑、直播适配度、社区维护；
- 不可控：同类市场窗口、主播网络放大、后来整个 extraction 品类对 Tarkov 的追随程度。

## 11. Verdict

### 成立

- Contract Wars 是 Battlestate / EFT 的真实能力与资金前史，不是无关旧作；
- 团队明确用较低风险项目“试技术 + 赚钱 + 学 FPS/Unity”，再进入高风险原创；
- EFT 的正式开发期严重低估了其此前团队与技术形成期；
- EFT 的独立性不是“没钱”，而是**先通过前作与早期直销制造自主融资条件**。

### 需要修正

- “Contract Wars → Hired Ops → Tarkov”不宜写成单线升级关系；Hired Ops 应视为 AbsolutSoft 的平行继承分支；
- “五个人凭低成本做出 Tarkov”类说法会把后续组织扩张、旧项目团队能力与在线基础设施全部抹掉。

### 不能推出

- Contract Wars 的收入是否足以覆盖 EFT 全周期成本；
- 没有 Contract Wars 就必然没有 EFT；
- 俄罗斯较低工资是成功的主因；
- 没有发行商 / 投资人就等于没有市场与融资系统。

## 12. Transfer

本案对其他独立团队真正可迁移的是“生产阶梯”，不是 EFT 的 scope：

1. **先做能活的项目，再做想做的项目**：第一阶段项目可以明确承担训练、现金流与组织验证职责；
2. **让前作支付技术学费**：尽量让未来核心技术栈在低风险项目中先经过真实玩家检验；
3. **保留能力，否定产品答案**：可以复用技术、人才和领域知识，同时彻底更换商业模型和玩法目标；
4. **用直销/EA 把市场接入转成 runway**：但必须把社区、支付、服务器、客服等成本计入；
5. **不要把最终组织规模投射回起点**：应追踪团队如何随着风险和收入逐层扩张。

## 13. Non-transfer

- Contract Wars 已形成的商业现金流与成熟 FPS 能力不是新团队可以瞬间拥有的；
- Russia 2028 / 枪械文化 / PMC 题材的长期积累具有团队特异性；
- EFT 后来的品类领导地位包含强烈时代窗口与右尾市场结果；
- 长达近十年的持续开发需要远超过“做出一个好原型”的组织耐力和现金流；
- 直接销售虽然减少平台抽成和约束，却要求团队自己承担大量发行基础设施。

- E002 — Nikita Buyanov / Dmitry Puchkov interview：Contract Wars 明确被描述为试技术、验证能力、赚钱继续开发；无投资人。
- E003 — GameSpot 2016 Nikita interview：EFT 的 hardcore 产品定义，以及拒绝 F2P / microtransactions。

## 15. Open Questions

1. Contract Wars 的实际收入、利润与向 Battlestate 初始资本转移的法律/财务路径是什么？
2. AbsolutSoft → Battlestate 的具体人员名单与时间线：谁离开、谁兼职/远程合作、谁留在 Hired Ops？
3. Contract Wars 与 EFT 之间是否存在可证明的代码、资产、工具或后端复用，而不仅是 Unity 技能与世界观延续？
4. Russia 2028 IP 在 AbsolutSoft / Battlestate 之间的权属与授权关系是什么？
5. 2016–2020 官网直销各阶段销量、版本结构和现金流如何支撑团队从早期规模扩大到数十人？
6. Twitch / YouTube 的关键放大节点分别是什么？需要建立可验证的市场时间线，而不是笼统写“主播带火”。
7. Hired Ops 作为同母体平行分支为什么没有得到 EFT 同等级的市场结果？这是本案最有价值的内部对照问题之一。

## 技术机会窗口与验证阶梯（2026-10-09）

- **技术条件（初步归档）：** 2010–17｜Contract Wars Unity Web Player。
- **实际体验验证与进入市场的路径：** 先有商业FPS技术+现金→Battlestate→预售Alpha。
- **机会类型：** `INHERITED+RECOMBINED`。不是对其原创程度的排名，亦不能凭此推出同代开发者的普遍选择。
- **尚缺证据：** 前作并非Mod；实际联网成本。未知项不得由2026年插件能力倒推。

## 深入审计：技术、规则与独立产品的实际关系（2026-10-09）

与`ARMA mod→PUBG`最重要的差别：`Contract Wars→Battlestate`是**已有商业在线FPS项目→新商业团队和高风险独立IP**。据Unity官方，旧项目制造了现金、Unity技能和多人协作能力；技术继承不是从未经商业运维的业余Mod开始，不能套“先免费UGC检验，然后融资”的线性神话。另一方面，Tarkov局内临时战局、局外持久用户资产，也是作者主动裁切持续模拟义务的设计选择；仍有高额技术债及真实运营成本未知，不能用“使用Unity”推运行便宜。来源：https://unity.com/made-with-unity/escape-from-tarkov 。
