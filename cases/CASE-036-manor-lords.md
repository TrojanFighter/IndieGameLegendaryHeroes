# CASE-036 — Manor Lords / Slavic Magic：“单人开发”是真的，但不是“一个人完成整条生产链”

- Case ID: CASE-036
- Subject: Greg Styczeń / Slavic Magic / Manor Lords
- Related Claims: C002, C003, C004, C008, C010, C011
- Period covered: c. 2017–2026
- Research status: RESEARCHING
- Corpus role: **SOLO-CORE BOUNDARY / GRANT-TO-OUTSOURCING / PUBLISHER MARKET-ACCESS / POLISH INDIE**
- Evidence Ledger: [`../evidence/CASE-036-manor-lords-source-ledger.md`](../evidence/CASE-036-manor-lords-source-ledger.md)

## 1. Why this case

Manor Lords 是研究 `solo dev` 边界的高价值样本，因为两个事实同时成立：Greg Styczeń 长期确实是 Slavic Magic 唯一 permanent studio member，并承担极强的产品作者角色；但完整 production perimeter 又包括 freelancers、purchased assets、QLOC QA 和 Hooded Horse 的 marketing/distribution。

这允许我们把“核心作者规模”与“完整生产链人数”严格分开，而不是在“真单人/假单人”二选一里打转。

## Myth

### Myth A — Manor Lords 是 Greg 一个人七年包办完成

不准确。Greg 公开说明早期靠视频自由职业维持；Patreon 与 Epic MegaGrant 后开始外包 mocap cleanup、illustrations 等专业工作。官方 FAQ 还明确列出资产采购、QLOC QA 与 Hooded Horse 的发行/市场外围。

### Myth B — 有外包和发行商就不能算 solo dev

也不准确。长期唯一 permanent studio member 与完整生产链存在外围劳动并不矛盾。更精确的描述是 `solo core / single permanent studio member + elastic production perimeter`。

### Myth C — Publisher 只是成功后接入渠道

现有材料不支持。Greg 说自己最初对 publisher 没兴趣，但 Hooded Horse 持续帮助处理媒体、商店、合作方等高机会成本工作，他明确认为合作增加了 wishlists。

## 2. Context–Situation–Action Snapshot

### Era / Production Regime

Manor Lords 成长于 Unreal Engine、Megascans/资产市场、Patreon、Epic MegaGrants、Steam wishlist/Next Fest、专业外包和全球数字发行高度成熟的时期。现代工具可以把底层技术、通用资产、QA 和市场接入外部化，因此“永久员工人数”越来越不能代表完整生产规模。

### Actor Situation

Greg 有多年业余游戏制作经验，但 Manor Lords 早期仍是 hobby/part-time 项目；他白天以视频自由职业接活维持生活，没有能力建立传统全职团队。项目逐渐获得社区支持和 grant 后，真正的瓶颈从“有没有时间”转为“哪些专业短板应由外部能力补足”。

### Action / Maneuver

|---|---|---|---|---|

### Anachronism Check

不能用 2025 年扩张后的团队规模倒写 2017–2023 的开发条件；也不能把 2024 年 Hooded Horse 的媒体/creator 网络当作 Greg 一开始就拥有的资源。反过来，也不能把早期 `solo core` 固化为项目永恒组织形态。

## Origin / Capability

Greg 表示自己从 RPG Maker 2000 等工具时期就开始做游戏，后来经过 Flash、Dark Basic 再进入 UE4。Manor Lords 是第一款“serious project”，但不是第一次制作游戏。

因此本案支持：**第一款正式商业大作，不等于能力资本从立项当天才开始。** Unreal 的 profiling、LOD、Material Editor、Data Tables、SDK/compatibility 等成熟工具也承担了大量原本需要内部技术团队负责的复杂度。

## Runway

可观察的 runway 阶段包括：视频自由职业 → Patreon → Epic MegaGrant → Early Access 销售。MegaGrant 的高杠杆用途不是“给钱组大团队”，而是先释放作者自己的 full-time 时间，再购买原本无法承担的专业外围。

## Production / Contributor Boundary

官方 FAQ 是极好的定义样板：Greg 是唯一 permanent studio member，但与越来越多 freelancers 合作，购买 Megascans 等资产，使用 QLOC QA，并由 Hooded Horse 负责 marketing/distribution。2025 年更新又显示 post-launch 已扩至多职能人员。

## Scope / Problem Redefinition

Manor Lords 不是主要靠把产品砍成极简来成立，而是通过**复杂度所有权重写**压缩组织：核心产品定义与关键工程留在作者手中；通用引擎承担底层技术；资产和 specialist work 外部化；QA、marketing、distribution 进一步外移。

## Market Access

Game Developer 基于发行商数据报道：Steam wishlists 超过 3.2m；Next Fest demo 期间增加约 500k，EA 前两周 press/influencer coverage 再增加约 800k。发行方同时承认销量规模远超预期，因此不能把 right-tail 爆发写成可预测公式。

## Preliminary Verdict

### STRONGLY SUPPORTED

- Greg 长期是唯一 permanent Slavic Magic studio member；
- 早期靠视频自由职业维持 hobby/part-time 开发；
- Patreon + Epic MegaGrant 后转 full-time 并扩大 outsourcing；
- freelancers、purchased assets、QLOC QA、Hooded Horse 都属于真实 production perimeter；
- publisher 介入包含具体市场/分发劳动；
- Early Access 成功后组织进一步扩张。

### ANALYTICALLY STRONG, STILL TESTING

- Manor Lords 的高作者一致性来自 `solo core + selective outsourcing`，不是“一个人包办所有工种”；
- non-dilutive grant 在这里的高杠杆用途是同时购买 author time 与专业外围；
- publisher 的重要价值之一是保护核心开发者免受高机会成本的 market-access labor 吞噬。

### NOT YET SUPPORTED

- 精确总预算与 Greg 的累计个人投入；
- Patreon / MegaGrant / publisher 各自资金规模；
- publisher 对最终销量的精确 causal share；
- solo core 天然优于普通小团队；
- 3.2m wishlists 的增长路径可普遍复制。

## Transfer

- 人数统计必须同时给 `core team` 与 `production perimeter`；
- grant 优先购买最稀缺的 full-time focus 与专业短板，不必先膨胀 permanent payroll；
- 外包不自动意味着失去产品控制；
- 发行商价值应拆成媒体 outreach、store optimization、partner calls、distribution、QA/porting coordination 等具体劳动；
- 成功后扩团队也应围绕已出现的 throughput bottleneck。

## Non-transfer

Greg 多年 Unreal 熟练度、Manor Lords 题材/视觉的市场吸引力、MegaGrant/Patreon 获得条件、Hooded Horse 网络和大规模 wishlist right-tail 都不能直接复制。

## Next verification

1. 建立 2017–2024 逐年开发/runway 时间线；
2. 重建 Patreon 与 MegaGrant 的时间和金额边界；
3. credits audit：freelancer、QA、music、mocap、art、porting；
4. 核 Hooded Horse 签约时 wishlist 基线与之后增长；
5. 跟踪 post-launch team expansion 是否改变 Slavic Magic 组织模型。

## Creator Life / Decision Audit

- **Audit status:** SUBSTANTIAL
- **Life stage:** 长期 hobby / part-time solo-core 创作者，早期靠视频自由职业维持；后在 Patreon / MegaGrant 后转 full-time。
- **Household:** relationship / children / housing / dependents `UNKNOWN`。
- **Runway:** video freelance income → Patreon → Epic MegaGrant → external freelancers / full-time focus → publisher market perimeter → Early Access sales。
- **Household burn:** `UNKNOWN`；但自由职业占用作者时间是明确 binding constraint，grant 的第一价值之一是买回 full-time focus。
- **Exit / recovery:** **MEDIUM / UNKNOWN** — 有可变现的视频自由职业能力，但转 full-time 后真实回撤能力未核。
- **Capability vector:** long-horizon Unreal / game-making generalist；product/engineering core 强；mocap cleanup、illustration、QA、marketing/distribution 等选择性外部化。
- **Problem ownership:** **HIGH** — 长期唯一 permanent studio member，核心 product thesis 与关键工程控制集中；publisher 主要补市场/分发外围。
- **Validation architecture:** hobby build / community → Patreon → MegaGrant → public wishlist / Next Fest → publisher amplification → Early Access → post-launch team expansion。
- **Reality adjudication:** **PARTIAL→STRONG market-side** — wishlist / demo / EA 提供强外部 truth；早期核心设计如何被 playtest 否决仍需补。
- **Capability capture risk:** **MEDIUM / UNKNOWN** — 强 Unreal/technical generalist 可能承担过多，但现有证据更支持 selective outsourcing，而非技术前沿自我吞噬。
- **Market sufficiency / legibility:** **STRONG** — 题材/视觉/城市建设定位可读性高，wishlist / Next Fest / EA 形成强需求信号。
- **Capability scaling:** **ELASTIC PERIMETER** — permanent core 极小，通过 assets、freelancers、QLOC、Hooded Horse 与 post-launch hires 补 throughput。
- **Major unknowns:** household economics、Patreon/MegaGrant 金额、publisher financing、个人累计投入、精确 freelancer/credit perimeter。
