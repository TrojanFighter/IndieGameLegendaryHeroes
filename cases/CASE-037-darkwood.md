# CASE-037 — Darkwood / Acid Wizard Studio：众筹“成功”以后，钱为什么不到一年就没了

- Case ID: CASE-037
- Subject: Acid Wizard Studio / Darkwood
- Related Claims: C002, C004, C005, C007, C010, C011
- Period covered: 2012–2019
- Research status: RESEARCHING
- Corpus role: **CROWDFUNDING-RUNWAY STRESS TEST / CONTRACT-WORK BRIDGE / EARLY-ACCESS EXTENSION / POLISH INDIE**
- Evidence Ledger: [`../evidence/CASE-037-darkwood-source-ledger.md`](../evidence/CASE-037-darkwood-source-ledger.md)

## 1. Why this case

Darkwood 是 FTL、Hollow Knight 等众筹正向案例的必要压力样本。Acid Wizard 的 Indiegogo 达到约 143% goal，但团队后来直接承认：他们按约一年完成项目估算资金，没有充分理解税、VAT、许可证、工作室、硬件、实体奖励、邮寄和推广成本；资金不到十二个月即耗尽，而项目总开发超过四年、Early Access 约三年。

因此本案研究的不是“众筹有没有用”，而是**gross funding、net runway 与 schedule uncertainty 之间的差别**。

## Myth

### Myth A — 众筹达到 143%，所以开发资金充足

错误。团队 2017 年回顾明确列出大量被忽视的非工资成本，并承认一年工期假设不现实。campaign 成功并没有自动产生足够完成项目的 runway。

### Myth B — 三个人没有职业游戏经验，说明经验不重要

不成立。三人此前主要是 hobby/game-jam 背景，这足以做出有吸引力的初始可玩物；但长期商业项目的 schedule、cost 和 scope 估算仍明显不足。原型能力与制作管理能力不能混为一谈。

### Myth C — Early Access 只是“没做完先卖”

对 Darkwood 而言，EA 同时承担 runway extension、真实用户反馈和持续市场接入。它是一次性 crowdfunding 之后的第二层生产融资结构。

## 2. Context–Situation–Action Snapshot

### Era / Production Regime

Darkwood 起步于 2012–2013 的 Kickstarter/Indiegogo 与 Steam Early Access 早期浪潮。众筹可以让陌生小团队直接接触全球玩家，但硬件、许可证、税费、实体 backer rewards 和物流仍会显著吞噬 gross pledge；EA 也远未形成今天这么成熟的行业范式。

### Actor Situation

三名创始人没有职业游戏开发履历，主要来自 hobby 与 Global Game Jam；早期还必须暂停原创项目接 paid contract work 维持生活。他们能做出足够有吸引力的 prototype/trailer，却缺乏对四年级商业项目的成本与工期估算经验。

### Anachronism Check

不能把 2013–2017 的 crowdfunding/EA 环境直接投射到今天，也不能因为 Darkwood 最终成功，就反推其早期一年预算“其实足够”。同样不能把三位创始人“没有职业游戏经验”误写成“没有任何可迁移技能”；这部分职业前史仍需继续核。

## Origin / Capability

2013 年同期采访明确说，三人此前主要是 hobby 制作和 Global Game Jam。Darkwood 从约 2012 年 11 月开始开发，中间需要停下来接付费委托。

这同时说明两点：game jam / hobby work 能积累快速制作与展示能力；缺乏长期商业制作经验又会提高 scope、schedule 与 runway 误判风险。

## Runway

至少存在三层：paid contract work → Indiegogo → Steam Early Access。团队后来的复盘非常清楚地说明：campaign gross amount 必须扣除税、VAT、licenses、studio、hardware、physical rewards、shipping 和 promotion，才能谈真实可用 runway。

## Production / Scope

三人核心高度压缩劳动，官方 FAQ 还说明音频由团队内部承担。但真正关键的生产动作不是“什么都自己做”，而是明确删除 multiplayer，把有限能力集中在 single-player 体验上。

## Failure / Estimation Error

Darkwood 的重大失败不是产品最终失败，而是早期**生产模型失败**：一年工期错误、成本项不完整、gross pledge 被高估为可用开发资源。最终四年以上开发证明 schedule uncertainty 本身必须进入预算模型。

## Market Access

Indiegogo campaign、backer alpha、Steam Early Access、社区反馈、正式发布与后续主机平台共同组成市场接入。团队称正式发布后几天销量接近此前三年 EA 销量的一半；这是开发者自报数据，只能作为销售波峰信号，不能当审计收入。

## Environment / Cultural Specificity

官方材料列出 Strugatsky brothers、Stanisław Lem 与 Slavic folklore 等灵感。可迁移的不是“东欧题材必然有市场”，而是低预算项目可以用作者熟悉的文化语汇形成差异化，同时避免追求写实大规模内容的成本结构。

## Preliminary Verdict

### STRONGLY SUPPORTED

- 三人此前主要是 hobby/game-jam 经验；
- 早期需要 paid contract work 维持生活；
- Indiegogo 获得近 3,000 backers、约 143% goal；
- 团队后来明确承认低估税费、许可证、空间、设备与 reward fulfillment；
- 约一年工期假设失败，资金不到十二个月耗尽；
- 总开发超过四年、EA 约三年；
- multiplayer 被明确删除以专注 single-player。

### ANALYTICALLY STRONG, STILL TESTING

- 缺乏长项目经验与 runway 误判之间存在合理关联，但还不能写成唯一原因；
- EA 是从一次性 crowdfunding 过渡到持续玩家融资/反馈系统的重要一层；
- 东欧文化表达既是作者性，也可能成为低成本差异化表面。

### NOT YET SUPPORTED

- 精确总成本与净利润；
- crowdfund 耗尽后各现金来源的占比；
- 所有设计删减都由现金压力导致；
- 波兰生活成本/政策是决定性成功因素；
- piracy/torrent stunt 对销量的精确贡献。

## Transfer

- crowdfunding 必须从 gross pledge 转成**净可用 runway**；
- 新团队要把 schedule uncertainty 本身计入预算；
- paid contract work 可作原创项目前期桥梁，但会切碎开发时间；
- EA 可以接替一次性融资，前提是已有值得付费的 playable core；
- 对极小团队，删除 multiplayer 这类高长期成本产品面往往比“每项少做一点”更有效。

## Non-transfer

Darkwood 独特美术/氛围、2013–2017 survival-horror/EA 市场窗口、创始人承受多年低工资的意愿、backer 社区和后续口碑都不能直接复制。
