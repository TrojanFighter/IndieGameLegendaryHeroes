# CASE-006 — R.E.P.O. / semiwork

- Status: RESEARCHING
- Subject: R.E.P.O. / semiwork
- Related Claims: C003, C004, C006, C008, C010, C011, C012

## Why this case

检验“突然冒出的极小团队 co-op 爆款”叙事。第一轮资料已经足以撤回旧的“3 人团队”假设：官方只稳定支持 **small indie studio / crew**，而不是一个可靠的固定三人头数。

## Myth

> 几个人看见 Lethal Company 火了，用 Unity 很快做出 R.E.P.O.。

当前证据反而显示：
- semiwork 此前用了约 6 年做 Voidigo；
- Voidigo 商业表现不足以保证下一项目，但提供真实的团队、制作、社群和收入前史；
- 团队把 Voidigo 获得的资金投入下一项目；
- R.E.P.O. 起于单人清扫恐怖 / found-footage 原型，而不是 Lethal Company clone；
- studio 此前没人使用 Unity，项目同时是引擎迁移；
- 从清洁→多人→搬运/税收/价值物提取经历多轮问题重构；
- Photon 承担 multiplayer engine / cloud hosting / scaling infrastructure。

## Capability Prehistory: Voidigo matters

semiwork 官方站点确认 Voidigo 是 R.E.P.O. 之前的作品；Steam/媒体资料显示 Voidigo 经历多年开发并完整发布。

所以不能从 2023/2024 的 R.E.P.O. prototype 开始计算团队能力：
- animation/art/music/game-development 协作；
- 完整发售；
- Discord/stream/devlog 等公开沟通；
- 失败/弱商业结果后的组织存续。

## Runway / Reinvestment

开发者公开制作史被多家专业媒体转述：
- Voidigo 六年开发让团队疲惫；
- 商业结果不足以安全保证下一步；
- 团队仍决定把前作赚到的钱投入 R.E.P.O.。

这是 C004 的非常强案例候选：
> 前作不仅是“能力训练”，也是下一次风险的内部资本来源。

但当前不能把“all the money”当作已审计财务数字。

## Failure Loop / Problem Redefinition

R.E.P.O. 特别值得研究的不是最终点子，而是多次主动抛弃旧问题：
- cleaning co-op 不好玩 → 删除清洁核心；
- moving game / tax collection 等主题反复更换；
- 最终留下 physics-based valuable-object extraction + horror + six-player cooperation。

“Let's just fail quickly”恰好与 Voidigo 的六年周期形成内部对照：团队在第二作主动追求更短的失败反馈循环。

## Technology / Hidden Infrastructure

这是第一次使用 Unity 的 studio transition；同时 multiplayer 并非全部自建：Photon 官方说明其技术承担 gameplay networking、global cloud hosting 与 scaling support。

所以“极小团队做大规模在线游戏”的解释必须包含：
> 通用引擎 + 专业网络中间件/云基础设施 = 被外部化的组织能力。

## Market

Voidigo 时期已经有：
- Discord；
- weekly Twitch streams；
- devlogs / social channels。

R.E.P.O. 又利用：
- Steam Early Access；
- creator/dev videos；
- streamer/VTuber；
- 极强的 social co-op observability。

因此市场能力也存在前史，不应写成“发布后纯算法偶然”。

## Preliminary Verdict

> R.E.P.O. 更像一个经历六年前作训练与有限商业回报的小工作室，把旧作资金、团队 tacit knowledge、公开社区能力、Unity 与 Photon 等外部基础设施重新组合，并通过更短的失败循环不断改写问题定义，最终撞上一个高传播性的 multiplayer product function。

## Creator Life / Decision Audit

- **Audit status:** PARTIAL / STUDIO-LEVEL
- **Life stage:** semiwork 已经历约六年 Voidigo 开发并完整 shipping；R.E.P.O. 是前作之后的第二阶段小工作室决策。
- **Household:** team members relationship / children / housing / personal burn `UNKNOWN`。
- **Runway:** Voidigo 收入被团队再投入下一作；具体金额未知；Unity / Photon 等外部基础设施降低 multiplayer production burden。
- **Household burn:** `UNKNOWN`；当前只能确认“前作钱被投入下一作”，不能把 studio cash 等同个人家庭 runway。
- **Exit / recovery:** `UNKNOWN` — 团队已有 shipping / community / technical skills，但个人职业 fallback 未公开。
- **Capability vector:** animation/art/music/game-development tacit capital + community communication；R.E.P.O. 期间增加 Unity / multiplayer middleware 使用能力。
- **Problem ownership:** **HIGH** — 团队多轮主动放弃 cleaning / moving / tax-collection 等方向，并重新定义成 physics-object extraction + horror + co-op。
- **Validation architecture:** Voidigo shipped experience/revenue → Project Clean / prototypes → repeated pivots → multiplayer build → Early Access → streamer/community amplification。
- **Reality adjudication:** **STRONG PROTOTYPE-SIDE** — “fail quickly” 成为对六年前作周期的主动反修正；多次概念被直接抛弃。
- **Capability capture risk:** **LOW / CONTROLLED BY PIVOTING** — studio 首次迁移 Unity 仍持续改产品，而不是把引擎迁移本身当成项目目标。
- **Market sufficiency / legibility:** **STRONG at launch** — physical comedy + co-op horror + valuable-object extraction 高观看可读性；exact prelaunch market signal 仍需拆分。
- **Capability scaling:** **PREVIOUS-GAME REINVESTMENT + EXTERNAL INFRASTRUCTURE** — 前作现金和 tacit capital 与 Unity/Photon 共同降低新项目门槛。
- **Major unknowns:** Voidigo 实际净收入、R.E.P.O. core headcount、founder household、contractor/QA/localization perimeter、streamer causal share。

## 深入审计：技术、规则与独立产品的实际关系（2026-10-09）

semiwork的多人转型可以作为`MIDDLEWARE-ABSORPTION`的可追源正例。现有Case已核团队此前并不熟悉Unity，且Photon承担多人网络与云托管；应进一步核Photon产品线/实际部署方式和成本。它不同于`Roblox→Standalone`：前作经验与收入是训练资本，但不能在无资料时编造一个已让玩家验证R.E.P.O.规则的前置UGC版本。

这个例子最值得拿来对照“造轮子”：成熟多人组件确实允许非专门网络工作室改变项目范围，但同样必须投入原型、社区、内容/主播传播和付费市场。供应商技术宣传的“帮助项目”不自动证明节省了多少具体人年，需采购合同或同期工程记录。
