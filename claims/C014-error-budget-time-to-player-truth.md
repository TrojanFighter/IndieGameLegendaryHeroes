# C014 — Error Budget / Time-to-Player-Truth

- Claim ID: C014
- Statement: 在高不确定度的 0→1 游戏生产中，较短的 time-to-player-truth 与“证据增强后再升级资源”的 escalation discipline 会降低单次方向错误的持续成本；当多人生态、内容 obligation、团队与资产规模在核心假设充分验证前升级时，error persistence cost 会显著上升。
- Scope: 高不确定度新玩法 / 新市场项目；不主张所有大型项目都应先做公开小原型。
- Status: SUPPORTED
- Last reviewed: 2026-10-06
- Related Cases: CASE-029, CASE-039, CASE-040, CASE-041

## Falsification Test

支持证据：
- 正向案例在较低承诺阶段获得真实玩家 / 社区反馈，再扩大投入；
- 负压力案例在核心假设仍变化时已经承担高团队、资产或 live-service obligation；
- 错误发生后，低承诺结构允许更快 pivot / kill / residual reuse。

反驳证据：
- 控制项目类型后，早反馈与 staged escalation 并不降低失败成本；
- 高承诺预投入在同类 0→1 中系统性更快、更便宜地找到 product truth；
- 所谓“快反馈”只是成功者事后选择性叙事。

必须控制：项目类型、网络效应、技术 R&D、IP / 品牌、团队经验和市场窗口。

## Evidence Against / Counterpressure

- Boundary 首日 >100k copies 说明长周期项目仍可能获得强 initial signal；失败并非“没有验证”一个变量能解释。
- Tripwire 的 mod/community 路径受 Unreal mod 生态与比赛窗口影响，不能机械复制。
- Gunfire 的完整早期 prototype 规模、预算和 internal greenlight 仍 UNKNOWN。
- SYNCED 可能留下技术、人才和 pipeline 残值；产品失败成本不能等同组织学习成本全部归零。

## Current Reading

四案例目前支持一个比“做 MVP”更精确的命题：

> 关键不是项目永远要小，而是资源承诺的升级速度应尽量跟随外部证据强度。

error budget 至少包括：
- 一次方向错误消耗多少现金 / 人月；
- 多久能知道自己错了；
- 错误期间新增多少不可逆 obligation；
- 失败后留下多少可复用技术、团队、社区与市场知识。

## Boundary / Forbidden Inference

不得推出：
- 大团队不能创新；
- multiplayer / GaaS 天生错误；
- 所有技术 R&D 都必须先向公开玩家验证；
- Early Access 自动降低风险；
- Boundary / SYNCED 的失败已经被单变量解释完成。

## Next Evidence Needed

1. Gunfire 最初 prototype 人数、周期与 internal greenlight。
2. NExT / SYNCED 更可靠的 headcount / budget chronology。
3. 至少一个“高前置投入但新玩法成功”的强反例。
4. 把 error persistence / residual value 编码到更多 0→1 案例。
