# Cross-Case Readings — 第一轮跨案例综合

- Status: ACTIVE
- Last reviewed: 2026-10-03

本文件不是书稿结论，而是把已经进入 Evidence Ledger 的 Case 反向用于检验 Claim。`SUPPORTED` 只表示当前材料允许使用该命题作为**工作性解释**；不得升级成必要条件、充分条件或普遍因果。

## C002 — sustainable runway > single financing event

**Status: SUPPORTED**

支持结构并不只有一种：
- FTL：个人储蓄购买最初几个月；
- Gunpoint：工资工作 / sabbatical 把大部分开发风险延后；
- Stardew Valley：兼职 + 伴侣收入支撑多年开发；
- Dwarf Fortress：玩家捐赠把一次性储蓄 fallback 转成长期 full-time runway；
- Kenshi：最低工资夜班维持多年，EA 收入再转为团队工资。

**边界 / 反例压力：** Kickstarter、publisher advance 等单次资金仍可能改变项目命运；本 Claim 目前没有建立严格的跨样本统计比较，只能说“可持续时间”在多种成功路径里反复出现，不能说其效应量一定大于融资金额。

## C003 — micro-team / OPC often rests on accumulated capability

**Status: SUPPORTED**

FTL、Gunpoint、Dream Quest、Project Wingman、Undertale、Lethal Company、Kenshi 等都显示：正式项目开始前往往已有职业经验、旧引擎、UGC/mod、前作、长期玩家品味或连续 ship 历史。

**边界 / 反例压力：** Stardew Valley 说明不能把“solo”一律解构成虚假标签；其 pre-launch core production 确实高度单人。正确结论是“solo 仍有前史/外围条件”，而不是“solo 不存在”。

## C004 — developers manufacture production conditions

**Status: SUPPORTED**

不同案例采用完全不同机制：
- Psyonix：work-for-hire 养组织与原创 IP；
- Gunpoint：工资 runway + GameMaker + revenue-share remote collaborators；
- Project Wingman：UE4 + online learning + public alpha + crowdfunding；
- Dwarf Fortress：text representation + patronage；
- Kenshi：night job + EA revenue-funded team expansion；
- R.E.P.O.：前作收益再投资 + Unity/Photon + 更短 failure loop。

**边界：** “制造条件”不代表可以无视住房、家庭、资本、平台、运气和市场窗口；它描述的是对可控变量的主动重组。

## C005 — work-for-hire can cross-subsidize original IP

**Status: SUPPORTED**

Psyonix 的直接创始人/设计负责人回顾足以证明“can”：公司长期通过 contract work 支付账单，同时保留小部分能力做原创，并从外包 AAA 项目中吸收制作流程与 Unreal 能力。

**边界：** 这是存在性命题，不证明 work-for-hire 通常是最优策略；合同项目也可能吞噬注意力、使原创长期延迟。

## C006 — AAA experience can help, but is not necessary

**Status: SUPPORTED**

正向：FTL 两位创始人有 2K Shanghai 经历；Lucas Pope 明确把 AAA 中“敢删功能、完成项目”的经验带入 Papers, Please。

反向：Dream Quest、Project Wingman、Undertale 等在没有传统 AAA 履历的情况下仍形成足够能力资本，来源包括长期玩家实践、数学/卡牌知识、UGC/mod、互联网学习和社区协作。

**边界：** 当前不能量化“大厂经历提高成功率多少”，也不能把非 AAA 路径浪漫化为更优。

## C007 — small teams redefine problem/cost structure

**Status: SUPPORTED, WITH REINTERPRETATION**

最初命题容易被误读成“小团队必须缩小 scope”。当前案例要求改成更一般的：

> **小团队往往重构单位功能/内容/表现的成本函数，而不一定缩小最终愿景。**

证据：
- Papers, Please：主动砍低 payoff / 高 implementation-cost 功能；
- Dream Quest：复用既有卡牌引擎、保持高度抽象表现；
- Dwarf Fortress：官方明确说 text graphics 允许加入更多内容；
- Kenshi：不是小 scope，而是用极长时间、低表现要求和先系统后团队的路径承担大 scope。

**边界：** 巨大 scope 仍可能失败；Kenshi/DF 是极端幸存者，不能反推“scope control 不重要”。

## C010 — market access is part of production

**Status: SUPPORTED**

开发与市场经常不是线性“做完→营销”：
- Papers, Please 的 public beta / Greenlight 热度直接让 Pope 延长约三个月 polish；
- Gunpoint devlog / videos / testers / Valve contact 构成开发期市场基础设施；
- Stardew Valley 通过 Greenlight 被 Chucklefish 发现，publisher 后续承担 business/marketing perimeter；
- Dwarf Fortress 的玩家社区直接提供捐赠 runway；
- Undertale 的 Homestuck audience 帮助 Kickstarter；
- Lethal Company 在 Patreon/playtest 阶段已经形成反馈/受众循环。

**边界：** “有市场接入”不等于“有传统营销预算”，也不意味着所有项目必须预先拥有粉丝。

## C011 — formal dev duration undercounts the real prehistory

**Status: SUPPORTED**

这是目前证据最密集的 Claim：
- FTL 前有 2K/college prototypes；
- Rocket League 前有多年 work-for-hire + SARPBC；
- Papers, Please 前有 Ratloop/serious games/Naughty Dog；
- Dream Quest 一周 prototype 前已有多年 card expertise + 一年旧引擎；
- Undertale 前有 RPG Maker / EarthBound hacks / Homestuck；
- Lethal Company 前有约十年 Roblox→Unity→多次 release；
- Dwarf Fortress 的设计/编程轨迹甚至追到童年。

**边界：** “有前史”不代表每一年都对最终产品具有同等因果贡献；后续应区分直接可迁移能力与宽泛人生经历。

## 尚未升级

### C001
已有 Stardew/FTL 等关于伴侣、储蓄与家庭条件的线索，但“福利/社会安全网”部分仍缺足够案例和可比环境数据。

### C008
Project Wingman、R.E.P.O. 等充分显示通用引擎/网络基础设施降低能力门槛，但命题后半段“同时提高竞争与可见性压力”尚未被同一证据链充分检验。

### C009
当前案例可说明开发者会拒绝某些成本假设，但“错误世界模型本身造成多少生产损失”仍缺可观察反事实。

### C012
需要真正的跨国家/地区/能力结构比较，不能用少量成功案例直接推出环境变量的异质效应。
