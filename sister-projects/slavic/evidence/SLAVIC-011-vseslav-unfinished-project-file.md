## 可复原的两段历史

| 时间 | 发生了什么 | 边界 |
|---|---|---|
| 1990年代早期 | Klimov 及合作者经营企业软件/Shareware；后转游戏，完成《Pike》 | 作者及参与角色需继续核实 |
| 1997 | 1C 提供《Vseslav》开发资金；设想中世纪罗斯队伍 RPG 与相关统一世界观项目 | **设想** 不等于实际运行过 |
| 1997年底 | 原计划推出但未完成；团队认为现有结果不足够特别，决定继续加入新机制 | 来自回顾访谈 |
| 1998危机后 | Snowball 扩大本地化、改造与发行国外游戏业务；为原创研发提供生存资金 | 跨业务现金流救了组织，但未证明拯救玩法 |
| 1999—2002 | 宣传出现马匹、易货、村庄生产、复杂 NPC 行为等设计；多次延期 | 大量宣传承诺 ≠ 有全功能可玩 build |
| 2002—2003 | 重心转向发行/本地化，原《Vseslav》逐渐搁置 | 当事人不记得某一次明确的“正式砍项”会议 |
| 2009 | 以《Долина четырёх ветров / Valley of Four Winds》方向重启：转向带地形/昼夜/季节约束的回合战术结构 | **已不是1997年原设计的简单延期** |
| 2009后 | 回顾称团队擅自改写为3D技术路线，原2D构建被拆，3D版本却未完成，项目再次停止 | 需复核版本控制/开发者多方证词 |

注意：文章标题的“13年承诺”覆盖**从初版构想至后续重启**，不可写作“一款同一范围的游戏持续完整开发十三年”。

## 核心失败解释：区分来源陈述与我们归因

**SUPPORT — 创始人回顾承认**：做了大量地点、文本和机制资产，却未先把一个场景的实际玩法做有趣；若有坚实制作约束，应先冻结一个可验证区域，然后才继续生产内容。

**SUPPORT — 资本与时间的反常效应**：Snowball 通过本地化/发行获得现金流缓冲，减轻了交付压力；回顾提到花三周调整农妇田间日程等细节。这可以说明**局部劳动投入并不自动转化为核心玩法验证**。

**SUPPORT — 第二次失败不同于第一次**：2009改造版有缩范围意图、旧资产复用和测试 build，却仍发生技术方向/组织监督问题。**不能用一个“scope creep”解释两次失败**。

**UNKNOWN — 合同与成本**：未取得 1C 的各轮预付款、绩效节点、游戏预算明细、全员年数/离职率、发行责任或代码仓库。不得断言“资金完全无限”“团队无压力”“老板允许一切”。

| 作品直接传承到后继名作 | 尚无实际机制或代码层对照 | NOT ESTABLISHED |

## 与幸存者对照的设计

- Krank/K-D LAB《Perimeter》：同样范围/技术野心极大，最终有产品发布；核项目强制收敛节点及发行责任。
- Gusarov《Space Rangers 2》：预算约7倍/周期约3倍仍发售；对照**社会与合约成本如何承受**。
- 2009《Valley of Four Winds》：同一组织不同版本的内部对照，观察 **scope contraction 是否因技术/治理变更失效**。
- 要另抽纯仿制、纯技术故障、无技术野心的失败作品，避免把所有失败都浪漫化为被埋没的杰作。

## 可迁移机制及历史时效

- 1997—2009 这条开发史是 HISTORICAL。
- “单个高风险设计问题先形成可玩的纵向切片，再开通大规模资产生产”可作为 DURABLE **候选制作规律**；但不意味着所有模拟型游戏必须采用相同原型比例。
- **不能**从某一原创项目夭折推出“独创性没有价值”；也不能推出“充足资金会害死开发者”。
